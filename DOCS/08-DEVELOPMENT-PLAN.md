## 2. Доводы порядка этапов

**Что это.** Этапы идут в порядке 0 → 7, и порядок — не удобство чтения, а требование: каждый следующий этап опирается на результат предыдущего и не может быть проверен без него.

**Зачем (довод).** Сначала закрывается документационный контур (этап 0): пока термины и числа не стабилизированы, код пишется под расплывчатую цель и переписывается. Далее строятся ядро и три базы (этап 1), потому что на них ложится всё остальное: без схем баз нельзя проверить ни конвейер, ни мастерскую. Затем вертикальный срез живого хода (этап 2) — до мастерской, а не после: нужен сквозной путь реплики, чтобы фоновые механики было к чему подключать и на чём тестировать. Мастерская (этап 3) идёт после среза, потому что её продукт — банки и пробуждение — потребляется живым ходом. Сид и языковые пакеты (этап 4) вынесены отдельно, потому что это большой батч, запускаемый распоряжением владельца, и он не должен блокировать код. Мир-антагонист и предсказания (этап 5) нужны поверх работающей сцены иначе их нечем измерить. Книга и UI (этап 6) собирают то, что уже случается в игре: сначала должна быть глава, потом её окно. Полное наследие симуляции (этап 7) — последним слоем на живой скелет: механики TNS35 переезжают целиком, но переезжать есть куда только после этапов 1–2.

**Пример.** Попытка сварить сид (этап 4) до схемы `base.db` (этап 1) даёт файл, который некуда загрузить; попытка строить Пифию (этап 5) до живого хода (этап 2) даёт предсказания, которые не с чем сравнить. Поэтому порядок фиксирован, параллельно этапу 0 допускаются только вертикальные срезы кода этапа 2 — с оговоркой: канон-источник не трогается до утверждения draft.

## 4. Этап 1 — ядро и данные

**Что делается.** Скелет движка с тремя базами, на который ложится всё остальное.

Шаги и исполнители:

1. Схемы баз по контрактам TNS35: literary-reader, world-db, WORLD_WRITERS, провенанс и статусы атласа. Исполнитель — код.
2. `base.db`: схема нарративов + загрузчик + счётчик векторов (`:5002`) при сборке. Исполнитель — код.
3. `world(name).db`: рецепт создания мира, анкета, пачка 96 карточек (16 × 6, канон). Исполнитель — код при рождении мира.
4. `literary.db`: перенос из папки движка в папку мира; сид-загрузка из языкового пакета. Исполнитель — код.
5. Фасад `:8000` + мост Telegram (только исходящие) + каркас web (WSS/cloudflared). Исполнитель — код.
6. Event sourcing (реплей и снапшоты) — наследуется целиком (п.15). Исполнитель — код.

**Критерий готовности.** Создание мира кнопкой → папка с тремя базами, анкета записана, пачка на месте, якорь выбран векторами.

## 5. Этап 2 — вертикальный срез живого хода

**Что делается.** Реплика → ответ, пусть простой, но сквозной: путь, который потом нельзя терять ни на одном этапе.

Шаги и исполнители:

1. Конвейер п.9: нарезка → лемматизация → векторизация → предвыбор → подтверждение → стоп-кран. Исполнитель — код.
2. Челнок: банк рутины + подбор по тегам. Исполнитель — код.
3. Пила (минимальная): настроение + вердикт «ткач / банк»; Селектор — заглушка с правом решать. Исполнитель — код; вердикт предлагает Пила, решает Селектор.
4. Ткач: слот модели (`:5001` или внешний), промпт из фактов движка; страховка по порогу молчания. Исполнитель — модель.
5. Биндер слотов: токены `[NPCname]`…, привязка в `world(name).db`. Исполнитель — код, без LLM.
6. Языковой пакет «русский»: pymorphy3 + лексикон намерений + запрет-списки + детекторы времени и настроения. Исполнитель — код (словарный сервис).
7. Стриминговая подкладка (хотя бы заготовки). Исполнитель — код + модель.
8. Коммит только подтверждённого в `world(name).db`. Исполнитель — код (стоп-кран).

**Критерий готовности.** Тест T4 проходится мыслью по коду; рутина отвечает за единицы секунд, пик — 30–60 с (канон, честная цена) со страховкой.

## 6. Этап 3 — мастерская

**Что делается.** Фоновая варка в паузах и ночью: всё, что не успевает и не должно успевать в живом ходе.

Шаги и исполнители:

1. Ступенчатый таймер пауз и очередь шагов; возобновляемость — с первого дня. Исполнитель — код.
2. Гефест / Forge: варка банков, fb2-вход, Цензор при варке, переплавка оседшего. Исполнитель — модель (варка) + код (конвейер).
3. Конвейер оседания: проверки → очистка → дедуп → авто-критик → уровни доверия. Исполнитель — код + малая модель (авто-критик).
4. Пробуждение главы (приоритет 1 очереди) + глубокий разбор первой реплики. Исполнитель — модель (заготовка) / код (очередь); глубокий разбор — один дешёвый вызов LLM.
5. Векторы судьбы дальнего круга (ступени 1–3) + offline-коммиты. Исполнитель — код.

**Критерий готовности.** Пауза 10 мин (канон) запускает механику; ночь 8 ч (канон) выковывает пробуждение; осевшая сцена переиспользуется по уровню доверия.

## 7. Этап 4 — сид и языковые пакеты

**Что делается.** Варка базового набора (сида) и сборка языковых пакетов по `basically-arcs-20261011.md`. Запуск — распоряжением владельца; до него план стоит.

Шаги и исполнители:

1. Шаг 1 / 1-бис: чистка сырья + подстановка токенов. Исполнитель — код.
2. Шаг 2: варка форм по 66 книгам (~840 архетипов, рабочее значение проекта). Исполнитель — модель (дешёвый слот, батч).
3. Шаг 3 / 3-бис: валидация + оракул выживания токенов + регекс-страховка. Исполнитель — код.
4. Шаг 4: фразовая подушка ×7 языков. Исполнитель — модель (переводной батч).
5. Шаги 5–6: словари лемм, упаковка русского пакета. Исполнитель — код + модель.
6. Шаг 7: остальные языки (en/de/fr/es/ja/zh) — отдельными распоряжениями. Исполнитель — модель.

**Критерий готовности.** `base.db` собрана, русский пакет стоит, метрики словарей отчитаны.

## 8. Этап 5 — Паганель, Пифия, мир-антагонист

**Что делается.** Слой, который держит мир бесконечным, читает игрока и противостоит ему.

Шаги и исполнители:

1. Паганель: atlas / forge edge / разведка пути; кольца и коридоры; UI-карточка с ключом; бюджеты. Исполнитель — код + внешний LLM (выпечка).
2. Пифия: карта игрока (ночные паттерны) + гороскоп (ветки, прогноз Пилы, темы варки); три ограждения. Исполнитель — код (сбор) + Гефест (куёт гороскоп).
3. Лица мира, эстафета, сопротивление чужому. Исполнитель — Селектор (решение) + код (передача напряжения по связям).
4. Сценарная рамка: дрейф якоря, держащий крючок, смена якоря. Исполнитель — код (эмбеддинги и сверка) + Селектор (крючок и смена).

**Критерий готовности.** Игрок не упирается в «край листа»; гороскоп ускоряет ответ; дрейф ловится ночью.

## 9. Этап 6 — книга и UI

**Что делается.** Всё, что игрок видит как книгу: от утра главы до эпилога.

Шаги и исполнители:

1. Утро главы (две ветки, таймер 30 с — рабочее значение). Исполнитель — код + заготовка (пробуждение).
2. Редактор + Цензор правок (1:1, контроль фактов). Исполнитель — внешняя модель (редактура) + код (проверка).
3. «Моя книга» (вкладки, правки игрока). Исполнитель — код (UI).
4. Анкета, заявка книги, смерть / финал / переигровка, эпилог. Исполнитель — код (обход) + игрок (решения).
5. Лайк / дизлайк + сигнал оседания. Исполнитель — код (сигналы), модель (регенерация по эскалации).
6. Админ-зона: менеджер моделей, журналы мастерской, распоряжения владельца. Исполнитель — код.

**Критерий готовности.** Книгу можно прочитать от пробуждения до эпилога; правки Редактора видны и отклоняемы.

## 10. Этап 7 — полное наследие симуляции (п.15)

**Что делается.** Механики весов, статов и структур мира из TNS35 наследуются целиком — это источник разнообразия мира. Потеря в этом классе не допускается; отказ — только явное решение владельца.

Состав наследия:

- экономика: economic-service, npc-economy, slave-economy, цены, циклы, налоги;
- здоровье и физиология; юнгианский профилировщик (14 метрик);
- романтические профили (romance-profiles);
- социальный граф всех форматов;
- deferred hooks, world validator, start resolver, диалоговый менеджер;
- лайк / дизлайк-наследие TNS35 (feedback-store, feedback-regen).

**Кто исполняет.** Перенос и подгонка — код; проверка поведения в мире TNS65 — прогоны и тесты, без участия человека в операционном контуре.

**Критерий готовности.** Перечисленные подсистемы подняты из TNS35 и работают в мире TNS65.

**Что это.** Живой репозиторий-наследие TNS35 — источник примерно двух третей кода TNS65. Вердикт расследования:

| Доля | Что | Куда |

| ~30% | brew / select | редизайн: batch → incremental |

**Порезано и не наследуется:** narrative-bootstrapper, story-planner, director-loop, villain-manager, user-agent, researcher-agent, wiki, cross-world-bus, feature-flags, intelligence/*.

## 13. Дисциплина исполнения

1. Маленькие задачи; одна задача = один коммит; после каждой — короткий статус владельцу (метод repair-card).
2. Каждый гейт называет исполнителя: код или модель (правило исполнителя).
3. Числа помечаются «канон / рабочее значение» (T6).
4. Термины — только по `GLOSSARY.md`; новый термин вносится туда.
5. Истина — код и канон, не пересказы; канон-источник не трогается до утверждения draft.
6. Тест любого изменения фичи: «книга интереснее для постороннего читателя» (критерий успеха).
7. State-First не трогаем: текст не переписывает outcome.
8. Фича с привкусом терапии или навязчивости — вне рамки.

## 14. Карта рисков

| Риск | Последствие | Митигация |
|---|---|---|
| Скорость локального станка (~5.6 ток/с, рабочее) | ход упирается в ожидание, игрок видит простой | гибрид (рутина из банка), стриминг, страховка, внешние слоты |
| Дрейф модели в рутине | повторяемое меняет форму, канон игры плывёт | рутина только из банка (п.3) |
| Потеря механик TNS35 | мир беднеет, исчезает источник разнообразия | п.15: наследие целиком; отказ — только распоряжение владельца |
| Следы источника в сиде | игрок видит след сырья в готовой заготовке | шаг 1-бис (токены) + шаг 3-бис (оракул + регекс) |
| «Рука мира» в книге | читатель чувствует ведение за руку, книга перестаёт быть игрока | заявка — не план; якорь невидим; ровно один мягкий толчок |
| Внешние API недоступны | глубокая сцена не рождается, ход умирает | деградация до локальной запаски, ход не умирает |

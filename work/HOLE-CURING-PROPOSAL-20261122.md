Замер 22.11: int7 на текущей базе зелёный (красный был на старой точке 080bf11, реестр листа 2) — задача не починка красного теста, а доведение термина до игрока.

**Проверка:** `go test -tags e2e ./e2e -run '^TestINT7$'` зелёный; в i18n.js игроковый ключ показывает «дайджест возврата»; пересечений терминов нет.

### T-17-08. Перенумерация закрытых волн с псевдонимами
Решение владельца 22.11. Метод:
- блоки задач закрытых волн получают новые ID в топологическом порядке — «Зависит от» ссылается только на меньшие номера;
- в каждом перенумерованном блоке под заголовком добавляется строка **«(прежний ID: T-XX-NN)»** — старый ID навсегда остаётся грепаемым;
- правятся только строки идентификаторов: заголовок блока, строка «Зависит от» (по вилке №2(б) шесть строк приёмки P9→P10 уходят в поле «Покрывает»), строка псевдонима. Остальной текст дословно;
- LEDGER не правится (строки закрытых волн остаются со старыми ID), git-история и коммит-месседжи не трогаются, 1032 упоминания T-XX-NN в Go-коде не трогаются — старый ID валиден через псевдоним;
- docs-check №5 принимает парность «строка LEDGER ↔ заголовок ИЛИ псевдоним»; №8 — массив `lin_exempt` (13 изъятий) удаляется, правило строго для всех;
- таблица соответствия старый→новый — `dev/TASK-RENUMBER-MAP.tsv`, генерируемая и воспроизводимая.

Глубина перенумерации — вилка №2. Затрагиваемые волны с нарушениями: 02, 03, 04, 05, 09, 13 (13 изъятий: 6 внутриволновых ссылок вперёд, 1 blocked-dep T-03-18→T-08-09, 6 приёмка P9→P10). Замер 22.11: T-09-01 — хаб (на него ссылаются 8 задач волны 09), на T-03-18 ссылается задача волны 08 — «простой перенос блока в поздний файл» ломает линейность зависимых; лечится топологической вставкой с каскадом, а для класса P9→P10 — сменой поля (вилка №2).
**Проверка:** docs-check ok (изъятий 0); каждый старый ID волн перенумерования грепается псевдонимом; карта соответствия воспроизводима.

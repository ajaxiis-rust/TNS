# Дистилляция — проект волны: найти и вылечить дыры

Дата: 2026-11-21. Статус: черновик на ревью владельца. Исполнение не начато.

Это предложение волны. После утверждения переносится в `fine/plan/16-distillation.md`
и разбирается на задачи с полными полями шаблона `_TEMPLATE.md` (сборка волны по
образцу P0). Ниже — проектные наброски задач: поля даны там, где уже содержательны.

## Зачем эта волна

Три беды, одна волна:

1. **Дрифт терминов.** Большая модель при сокращении текстов придумывает новые
   слова для старых понятий; слова попадают в документацию, из неё — в планы и
   код. Уже случалось: «конвейер/пайплайн/алгоритм хода», терминологическая волна
   21.11 с четырьмя коммитами и grep-гейтами.
2. **Дыры механик не видны снаружи.** У мастерской нет сквозного теста (int-тесты
   её не гоняют, только редакторский контур в int7 и нарезка в int6). У рождения
   не влит словарь классификации якорей (`work/IMP9-dict-adds.json`, 13 КБ) и не
   откалиброваны веса (anchorLemmaBoost=0.15, порог подбора), а сквозной тест
   гонит эмбеддер с заглушкой `--fake-embed` — качество подбора не измеряется
   нигде.
3. **Словарь определён в четырёх местах по-разному.** `GLOSSARY.md`,
   `dev/GLOSSARY.md`, `fine/04-spec/00-glossary.md`, «краткий словарь» в
   `DOCS/00-START-HERE.md` — при законе «термин вносится в словарь, а не в текст».
   Дрифт начинается прямо в справочном слое.

Дистилляция — снять с кода правду о структуре (какие файлы реально реализуют
каждую механику), сравнить с описаниями, развести расхождения решениями владельца,
навести порядок в словаре и удержать результат проверкой на записи.

## Границы волны

- **Правится:** документы, словари, скрипты проверок, настройки `.grok/`.
  Код движка не правится.
- **Не-цели:** TNS75; переводчик EN/RU; калибровка весов; переименование
  замороженных имён (21.11); `RAW/`, `brief3.md`, исторические строки
  `99-LEDGER.md`.
- **Анти-цели:** новые определения терминов вне якорных файлов; свободное
  переформулирование текстов моделью (правки — механические по таблице;
  решения — владелец).
- **Известное лечение, в волну не входит** (вторая волна, формируется из
  реестра): влить `work/IMP9-dict-adds.json`; бенч калибровки весов якоря по
  образцу леммабенча (золотой набор «анкета → якорь», живой эмбеддер, доля
  вынужденного якоря); сквозной тест мастерской.

## Порядок задач

Порядок исполнения задаёт «Зависит от», не номер. В этой волне — линия,
зависимости смотрят только назад, параллелей нет.

### T-16-01. Инвентаризация дыр механик (инфраструктура; только чтение)
- **Зависит от:** пусто.
- **Шаги:**
  1. Составить список механик по `DOCS/00-START-HERE.md` и `DOCS/01-OVERVIEW.md`
     (рождение, живой ход, пауза, оседание/мастерская, рутина/Челнок, нарезка,
     дайджест, экспорт, пробуждение, модели, телеграм, Пифия, банки).
  2. Для каждой механики найти сквозной тест в `engine/e2e/` (int1–int11) или
     записать «нет».
  3. Для каждого сквозного теста выписать заглушки из его флагов
     (`--fake-embed`, `--fake-slot`, `--fake-clock`) и что из-за них не
     измеряется.
  4. Выписать незакрытые работы из `work/`: какие файлы, чего им не хватает до
     влития (известный случай — `IMP9-dict-adds.json`).
  5. Выписать неоткалиброванные величины с путями до строк кода (вес
     `anchorLemmaBoost=0.15` в `engine/internal/birth/anchor.go`, порог подбора
     якоря `matchThreshold`).
  6. Свести в лист 1 реестра.
- **Создаётся:** `work/DISTILLATION-REGISTRY-20261121.md`, лист 1 «дыры».
  Колонки: механика | сквозной тест | заглушки | юнит-покрытие | незакрытая
  работа | статус волны (закрыто / идёт / фича / нет волны) | источник.
  Решение владельца 21.11: `internal/senses` — не дыра, а фича для
  калибровки (только разработка, с деплоем не связана); статусная колонка
  обязательна, чтобы реестр не поднимал тревогу на идущих волнах.
- **Проверка:** каждая строка листа 1 имеет заполненную колонку «источник»;
  механик в листе не меньше, чем в `00-START-HERE.md`.
- **Решение владельца по итогам:** выбор механики-пилота из данных листа 1.

### T-16-02. Карта кода: пакеты, вызовы, сообщества файлов (инфраструктура; только чтение)

     typed_complete. Цифры совпали с отчётом старой машины от 18.11.
  3. Снять список пакетов и файлов: `go list ./...`.
  4. Прогнать int1–int11 по одному с `-coverprofile`; собрать таблицу

### T-16-03. Пилот: полный проход метода на одной механике
- **Зависит от:** T-16-01, T-16-02 (механику выбирает владелец из листа 1).
- **Шаги:**
  1. Взять механику по решению владельца.
  2. Наложить сообщество файлов (лист 2) на пункт канона; каждое расхождение

     канона без файла») — строкой в лист 3.
  3. Эвристика «имя ↔ содержимое»: для каждого файла сообщества сравнить имя с
     тем, что он объявляет (типы, функции); расхождения — в лист 3.
  4. Откалибровать формат листа 3: посчитать ложные срабатывания, записать
     оценку и уточнения правила.
- **Проверка:** владелец согласен с листом 3 пилота; доля ложных строк

- **Исполнитель:** модель (анализ) + владелец (приёмка).

### T-16-04. Словарь-якорь: схема записи, решения, машиночитаемая таблица
- **Зависит от:** T-16-03.
- **Шаги:**
  1. Утвердить схему записи: термин (не больше двух слов) — суть одним
     предложением — кодовый идентификатор — запрещённые синонимы — ссылка на
     пункт канона.
  2. Модель готовит драфты записей по трём доменам: игра (`GLOSSARY.md`),
     разработка (`dev/GLOSSARY.md`), спека (`fine/04-spec/00-glossary.md`) и
     список коллизий. Омонимы развести по употреблениям (случай: «Цензор» в трёх
     смыслах «различать по месту»).
  3. Владелец решает каждую коллизию; решения записываются.
  4. Переработать якорные файлы по схеме; замороженные имена (21.11) не
     переименовывать.
  5. Сгенерировать машиночитаемую таблицу из якорей: термин | пакет/идентификатор
     | файлы | раздел канона | запрещённые синонимы. Место: `GLOSSARY-TERMS.tsv`
     рядом с корневым глоссарием (если владелец выберет другое — перенести).
     Таблица генерируется из глоссария, руками не редактируется.
- **Правится:** `GLOSSARY.md`, `dev/GLOSSARY.md`, `fine/04-spec/00-glossary.md`.
- **Создаётся:** `GLOSSARY-TERMS.tsv`, генератор таблицы (скрипт в
  `engine/scripts/`).
- **Проверка:** каждая запись якорей соответствует схеме (ревью владельца);
  `cd engine && scripts/docs-check.sh` → exit 0.
- **Документы:** сами якоря — источник; зеркала чистятся в T-16-05.

### T-16-07. Гейт удержания на запись (ступени A и B; C — журнал)
- **Зависит от:** T-16-04.
- **Шаги:**
  1. Ступень A — скрипт проверки запрещённых слов: буквальный поиск, без учёта
     регистра, список из `GLOSSARY-TERMS.tsv`.
  2. Ступень B — лемма-сверка текста с таблицей через резидентный
     `tns65-lemmaru`: ловит морфологические варианты, которые буквальный поиск
     пропускает.
  3. Ступень C — журнал кандидатов-чеканок: существительные вне словаря и
     стоп-слов. Только запись в журнал, ничего не блокирует.
  4. Навесить проверку на запись `*.md`: PostToolUse-хук в `.grok/settings.json`
     на `write|search_replace`; нарушение возвращается модели замечанием, модель
     исправляет в том же ходу.
  5. Диапазон: живой набор из T-16-06; never-edit пути исключены.
- **Проверка (приёмка владельцем):** в живой сессии записать файл с запрещённым

  проходит с задержкой не больше секунды; `RAW/` и леджер не проверяются.
- **Исполнитель:** код (скрипты и хук) + владелец (приёмка).

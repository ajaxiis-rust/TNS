# Правила переписывания DOCS/TNS65

Использовать при правке любого файла `DOCS/*.md`. Лежит в проекте; наружу проекта не выходить.

## Язык и стиль

1. **Технический русский, не сленг.** Никаких «кухня», «бой», «замок» в значении ограничения, выдуманных метафор для технических состояний. Слово «бой» в проекте запрещено.
2. **Только термины из `GLOSSARY.md`.** Новый термин не вводится мимо словаря.
3. **Полные предложения, одно действие — один абзац.** Не перечень обрывков. Связи между мыслями проговаривать: «поэтому», «в результате», «однако», «далее». Списки — только для действительно перечисляемого (шаги, файлы, варианты, таблицы).
4. **Конкретно и подробно, без воды.** Не канцелярит. Не сжимать до формулы с пропущенными шагами.
5. **Понятно постороннему разработчику** с первого прочтения.

## Структура смыслового блока

1. **Что это** — 1–3 предложения.
2. **Зачем (довод)** — почему так, а не иначе; альтернатива и причина отказа, если есть в источниках. Довод — факт или арифметика.
3. **Пример** — конкретный сценарий с именами, числами, таймингом.

Для механизмов: **кто исполняет** (код или модель) и **что пишет/читает** (какая база).

## Формулировки владельца

Сохранять дословно:
- «Пиши свою книгу просто играя»
- «Язык — упаковка данных, не архитектура»
- критерий успеха: книга интереснее для постороннего, который не знает автора
- правило исполнителя: каждый гейт называет код или модель

## Чего не делать

- Не включать журналы решений и историю обсуждений.
- Не выдумывать цифры. Помечать «канон» / «рабочее значение».
- Не менять смысл пунктов 1–21 и имена ролей.
- Не создавать новые файлы DOCS — переписывать 00–09.

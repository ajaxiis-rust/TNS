# Маршрутизация внешних провайдеров по задачам

Статус: дизайн, 2026-11-14. Решение владельца: сначала план; внутри списка задачи — ротация по кругу с откатом. Код не начат.

## 1. Что хочет владелец

- Игрок выбирает модель из списка и вставляет свои ключи.
- Запросы идут по его списку провайдеров по очереди, с откатом: быстрее и дешевле.
- Разные задачи можно назначить разным провайдерам: например, Паганель — Gemini, обработка книг — MiMo.

## 2. Текущее состояние (факты кода)

- Реестр провайдеров и цены — `engine/providers.toml` (`internal/providercfg`), ключи и выбранная модель — `settings.toml` (`<имя>`, `<имя>_model`).
- Чат (Ткач) собирает **один** слот на старте ядра: `DefaultChatWeaver` (`internal/webapi/chat_weaver_pack.go`) по `slots.default` из `config.yaml`; смена провайдера — правка конфига и перезапуск.
- Обработка книг (`internal/workshop`) ходит через `slotForProvider` / `workshop.SetSlot`, но в проде `SetSlot` не вызывается: генерация книг сейчас не подключена к модели (P4). `model_bindings` заполняются, но рантайм их не читает.
- Паганель-разведка (`internal/paganel/scout.go`) — заглушка `GET http://paganel.example/research`; к модели не подключена, `key_ref` из `config.yaml` не используется.
- Рейтинг 18+ уже запрещает внешние слоты: `workshop.ProviderForRating` возвращает `local`.
- Счётчики вызовов: `engine/state/usage.jsonl`, строки `{role, calls, tokens, cost_millis}` (`models.AppendUsage`), читаются монитором и карточками.

## 3. Термины

- **Провайдер** — запись `[[providers]]` в `providers.toml` (имя = ключ в `settings.toml`).
- **Модель** — выбранная игроком модель провайдера (`<имя>_model`, иначе `default_model`).
- **Маршрут** — упорядоченный список имён провайдеров для задачи.
- **Задача** — `chat` (Ткач), `books` (мастерская), `scout` (разведка Паганеля).

## 4. Данные игрока

Маршруты — в `settings.toml` плоскими ключами (формат файла не меняется, UI уже умеет писать произвольные ключи):

```toml
deepseek = "sk-..."
deepseek_model = "deepseek-chat"
mimo = "sk-..."
mimo_model = "mimo-v2-flash"
gemini-flash = "..."
gemini-flash_model = "gemini-3.8-flash"

route_chat = "deepseek,mimo,gemini-flash"
route_books = "mimo,qwen"
route_scout = "gemini-flash"
```

Правила:

- Порядок в строке — порядок ротации. Пустая строка/ключа нет — задача использует запасной маршрут: `route_chat` → `slots.default`, `route_books` → `slots.default`, `route_scout` → выключена.
- Допустимы только имена из `providers.toml`; неизвестное имя — 400 при сохранении, а не молчаливое выпадение.
- `local` разрешён последним элементом цепочки (локальная запаска :5001); в середине — предупреждение в UI (локальная генерация медленная).
- Модель берётся из `<имя>_model`; у каждого провайдера своя. Один провайдер в маршруте — одна модель.
- Ключ пустой — провайдер пропускается при выборе (не ошибка: игрок мог ещё не ввести ключ); если пропущены все — деградация по правилам задачи.

## 5. Роутер

Новый пакет `internal/providerroute` (без зависимостей от webapi):

- `Route` — список имён; `Router` — маршруты по задачам + атомарные курсоры.
- Выбор на запрос: `calls(task) % len(alive)` — первый провайдер, затем следующие по кругу. Курсор в памяти процесса, сбрасывается при перезапуске (детерминизм в тестах — подменяемые часы/курсор).
- Откат: на ошибку соединения, тайм-аут, 429, 5xx, отказ ключа (401/403) — следующий провайдер. `netgate.ErrDeniedHost` — тоже откат (хост не в списке).
- Не откатывать: 400 «плохой запрос» (промпт/модель), отказ цензора по содержанию (это не отказ провайдера), ошибку после первого отданного чанка — поток уже виден игроку, повтор дал бы дубль прозы; ход идёт по существующей деградации (`slot.degraded`).
- Все провайдеры отказали: чат — существующая запасная запись `fallbackReply` и путь `fallback`; книги — лестница `GenerateWithRetry` и `ErrForgeDegraded`; разведка — `ErrScoutDisabled`-подобный пропуск (ход не блокируется).
- 18+: если рейтинг мира 18+, маршрут принудительно `local` (существующее правило), внешние провайдеры не вызываются вовсе.
- Стоимость/лимиты: каждый вызов пишется в `usage.jsonl` с полем `provider` (расширение формата, старые строки без поля читаются как раньше). Ротация распределяет лимиты; цена не сортируется (порядок задаёт игрок).

## 6. Точки подключения

### 6.1 Чат (этап 1, обязательный)

- `DefaultChatWeaver` собирает `RoutedProseSlot` (`turn.ProseSlot`): на каждый `Stream` роутер выбирает провайдера, строит/берёт из кэша клиент (`models.ProviderClient` / `models.OpenAIClient`) и стримит. Ошибка до первого чанка — следующий провайдер; после первого — как сейчас.
- Ключи и модели читаются на старте (как сейчас), маршрут — тоже; изменения применяются после перезапуска. В UI — предупреждение.
- Путь хода остаётся «weaver»; при откате пишется событие журнала (см. §8), `slot.degraded` — только при полном отказе.

### 6.2 Книги (этап 2)

- `workshop.Slot` (`Generate(ctx, role, prompt)`) получает адаптер `RoutedWorkshopSlot`: тот же роутер, задача `books`. Провайдеры — из `route_books`.
- Подключение: `workshop.SetSlot(...)` в `cmd/tns65/main.go` (сейчас не вызывается). Это одновременно закрывает P4-проводку слота мастерской; без неё маршрут книг не проверить.
- Гранулярность на этом этапе — задача `books` целиком. Пословная привязка ролей (`analysis`, `prose`, `editor`, `censor`) остаётся в `model_bindings` и может стать этапом 3: `route_books.<роль>`.
- `ladder` уже делает три ступени и деградацию; роутер встраивается в `slotForProvider`, чтобы каждая ступень могла идти к следующему провайдеру.

### 6.3 Паганель (этап 3)

- Заменить заглушку `Scout.Fetch` на реальный чат-вызов: промпт разведки → OpenAI-совместимый или Gemini-клиент по `route_scout`; `key_ref` в `config.yaml` остаётся ссылкой на ключ по умолчанию, если маршрут пуст.
- Сохранить бюджет сессии, тайм-аут и правило «пропуск не блокирует ход».

## 7. API

- `GET /api/providers/routes` → `{"routes":{"chat":["deepseek","mimo"],"books":["mimo"],"scout":[]},"warnings":[…]}`.
- `PUT /api/providers/routes` `{"task":"chat","providers":["deepseek","mimo"]}` → проверка имён и дублей, запись `route_<task>` в `settings.toml`, ответ `{"status":"ok","restart_required":true}`.
- Ошибки: `bad_request` (неизвестный провайдер, дубль, пустой список при непустом ключе), `internal` (запись файла).
- `GET /api/providers` расширяется полем `routes` (какие задачи используют провайдера) и `key_set`, чтобы карточка показывала участие в маршрутах.

## 8. Наблюдаемость

Новые константы журнала (`internal/journal/events.go`, список в DOCS/10 §6):

- `route.changed` — сохранён маршрут задачи (task, order).
- `provider.rotate` — выбран провайдер по кругу (task, provider, index).
- `provider.failover` — откат (task, from, to, error).
- `provider.exhausted` — все отказали (task, errors_count).

`usage.jsonl`: поле `provider` (необязательное), чтобы монитор показывал расход по провайдерам; строки без поля — «unknown».

## 9. UI

В разделе «Провайдеры» — блок «Маршруты» над карточками:

- Три задачи: «Чат», «Обработка книг», «Паганель (разведка)».
- Для каждой — упорядоченный список: добавить провайдера из выпадающего списка, поднять/опустить, убрать. Показывать модель и наличие ключа; провайдер без ключа — приглушён и помечен, но выбрать можно.
- Подсказка: «Запросы идут по кругу; при ошибке — следующий. Изменения применяются после перезапуска движка».
- Пустой список — «не задан»: задача падает на `slots.default`.
- Проверка текстов интерфейса: без «станк»/«станци» (существующий `TestUITextsWithoutStationSlang`).

## 10. Ограничения и риски

- Дублирование платных вызовов: повтор после первого чанка запрещён; откат только до первого чанка.
- Разные модели/форматы: у Gemini и OpenAI-совместимых один промпт, но разное качество; откат может дать стилистический скачок. В журнале видно, кто ответил.
- Лимиты: ротация помогает от 429, но не от общего бюджета игрока.
- Ключи: по-прежнему только `settings.toml` 0600, наружу не отдаются.
- Рейтинг 18+ — внешние маршруты не работают; UI должен явно показывать это для мира 18+.
- Перезапуск: маршруты и ключи читаются на старте; live-правка только для карточек/списков (как сейчас).

## 11. Тесты и гейты

- `providerroute`: ротация по кругу (N вызовов → равномерно), пропуск без ключа, откат на каждой категории ошибок, отсутствие повтора после первого чанка, all-fail, изоляция курсоров задач, 18+ → local.
- `turn`: `RoutedProseSlot` поверх двух фейковых провайдеров — ответ второго после ошибки первого; счётчик вызовов.
- `webapi`: GET/PUT маршрутов, валидация, запись `settings.toml`, `restart_required`, карточки с полем маршрутов.
- `workshop`: адаптер `RoutedWorkshopSlot` на фейках; существующая лестница не ломается.
- `paganel`: разведка идёт по маршруту, бюджет/тайм-аут сохранены.
- `go build ./...`, `go vet`, `go test` затронутых пакетов, `scripts/docs-check.sh`; UI — браузер на изолированном экземпляре (карточки, редактор маршрутов, сохранение, перезапуск).
- Известный флейк `internal/supervisor TestNoShortReadyBudget` не считать регрессией (воспроизводится на HEAD).

## 12. Этапы

1. **P1. Роутер + чат.** `internal/providerroute`, `RoutedProseSlot`, `DefaultChatWeaver` по `route_chat`, события журнала, usage.provider, тесты. Критерий: два провайдера с ключами, второй отвечает после ошибки первого; ротация видна в журнале.
2. **P2. UI и API маршрутов.** `GET/PUT /api/providers/routes`, блок «Маршруты», предупреждение о перезапуске, проверка текстов. Критерий: игрок собирает список, он сохраняется и переживает перезапуск.
3. **P3. Книги.** `RoutedWorkshopSlot`, `workshop.SetSlot` в `main.go`, задача `books`. Критерий: варка книги идёт через маршрут, при отказе — следующий провайдер; без ключей — текущая деградация.
4. **P4. Паганель.** Реальный вызов модели по `route_scout`, сохранение бюджета/тайм-аута. Критерий: разведка отвечает выбранным провайдером, при отсутствии ключей — пропуск, ход не блокируется.

Каждый этап — отдельный коммит с тестами и правкой DOCS/10; P3 и P4 затрагивают незавершённые узлы (P4-проводка мастерской, заглушка разведки) и требуют отдельной проверки на копии прода.

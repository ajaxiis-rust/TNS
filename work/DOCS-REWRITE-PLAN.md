# План переписывания DOCS — нормальный язык + доводы + примеры

Заказ: переписать все `DOCS/*.md` (00–09) нормальным техническим языком, с доводами и примерами.
Работать только внутри `/media/ajaxiis/ext3/TNS65`.

## Правила языка

1. **Технический русский, не сленг.** Без «кухни», без «боя», без выдуманных метафор для технических состояний.
2. **Только термины из `GLOSSARY.md`.** Новый термин мимо словаря не вводится.
3. **Полные предложения.** Одна мысль — один абзац. Связи проговаривать: «поэтому», «в результате», «однако», «далее». Списки — только для шагов, файлов, вариантов, таблиц.
4. **Конкретно, без воды.** Не канцелярит и не «довод здесь в надёжности», но и не сжатие до обрывков.
5. **Понятно постороннему разработчику** с первого прочтения.

## Структура смыслового блока

Порядок фиксированный:

1. **Что это** — 1–3 предложения обычным определением.
2. **Зачем (довод)** — почему так, а не иначе; альтернатива и причина отказа, если есть в источниках. Довод — факт или арифметика.
3. **Пример** — конкретный сценарий (мир игры или железо): имена, числа, тайминг.

Для механизмов дополнительно: **кто исполняет** (код или модель, роль из словаря) и **что пишет/читает** (какая база).

## Формулировки владельца

Правила владельца сохранять дословно, не пересказывать:
- «Пиши свою книгу просто играя»
- «Язык — упаковка данных, не архитектура»
- успех: книга интереснее для постороннего, который не знает автора
- каждый гейт называет код или модель

## Чего не делать

- Не писать журнал решений и историю обсуждений.
- Не выдумывать цифры; канон / рабочее значение — помечать.
- Не менять смысл пунктов 1–21 и имена ролей.
- Не создавать новые файлы DOCS — только переписать 00–09.

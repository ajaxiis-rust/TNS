# bench — бенч скорости моделей станции

Замеряет производительность `*.gguf` из `world_db/models` станции и подбирает
оптимальные числа потоков для `config.yaml`. Замеры делает `llama-bench` —
штатный бенчмарк из поставки llama.cpp (сторонний инструмент, ставится вместе с
`llama-server`; здесь используется `~/.local/bin/llama-bench`).

## Зачем

Настройки `gen_threads`, `embed_threads`, `gen_ctx`, `gen_parallel` в
`config.yaml` напрямую задают `-t`, `-c`, `--parallel` при спавне
`llama-server`. Числа в комментариях конфига (например «7 потоков 2.2 tok/s
против 3.3 на 3 потоках») добывались вручную. Этот стенд делает замер
воспроизводимым и печатает готовые строки для конфига.

## Запуск

```bash
bash engine/bench/run_bench.sh                  # quick: все модели, CPU
bash engine/bench/run_bench.sh --mode full      # полная сетка, CPU и Vulkan
bash engine/bench/run_bench.sh --mode smoke     # проверка стенда за секунды
bash engine/bench/run_bench.sh --models-dir /путь/к/моделям
```

Результаты — `engine/bench/results/<дата-время>-<режим>/`:

- `<роль>__<модель>__ngl<N>.json` — сырой вывод `llama-bench`;
- `manifest.json` — машина и параметры прогона;
- `summary.md` — таблицы pp/tg по потокам и рекомендации `gen_threads` /
  `embed_threads`;
- `llama-bench.log` — stderr инструмента.

## Режимы

| Режим | Потоки | pp / tg | Повторы | Устройство | Когда |
|---|---|---|---|---|---|
| `smoke` | 1, 4 | 64 / 16 | 1 | CPU | проверка стенда |
| `quick` | 1, 2, 3, 4, 6, 8 | 256 / 32 | 2 | CPU | быстрый подбор |
| `full` | 1..8 | 1024 / 128 | 5 | CPU и Vulkan | чистовые цифры |

## Как читать сводку

- **pp t/s** — обработка промпта (скорость чтения контекста, для эмбеддера это
  и есть вся работа).
- **tg t/s** — генерация токенов (скорость ответа игрока). Для генеративных
  моделей оптимум по tg важнее — на нём строится рекомендация `gen_threads`.
- Роль модели берётся из имени папки (`analysis`, `embed`, `weaver`, …).
  У `embed` замеряется только pp (`-embd 1 -n 0`).

## Связь с config.yaml

| Поле конфига | Что меряет бенч |
|---|---|
| `gen_threads` | оптимум tg по сетке `-t` |
| `embed_threads` | оптимум pp по сетке `-t` для модели `embed` |
| `gen_ctx` | сам бенч не меняет, но KV-кэш растёт с контекстом — при нехватке ОЗУ снижать именно его |
| `gen_parallel` | в замерах 1; на этой машине больше 1 не даёт выигрыша |

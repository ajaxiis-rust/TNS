# P7. Интерфейс

Цель волны: игрок получает рабочий веб-интерфейс — чат, Атлас, История, MCP,
Настройки и Мониторинг — на loopback-порту станка, с рендером на стороне браузера и
статикой без сборщика. Доставка остаётся единым статичным бинарником: HTML, CSS и
JS встраиваются в ядро и раздаются с `127.0.0.1:8720`; на машине игрока нет ни
Python, ни Node, ни сборщика фронтенда.

Задачи волны идут слоями: первым — каркас меню и раскладка, затем веб-сервер на
loopback и исходящий туннель, дальше экраны по одному (Атлас, История, MCP,
Настройки, Мониторинг) и сквозные правила — единственный пользователь, неизменность
мира, функциональные имена, счётчики внешних слотов. Каждая задача закрывается
тестом HTTP-хендлеров (`go test ./internal/webapi -race`) и статическим сканом
`bash engine/scripts/ui-lint.sh`; проверка JS идёт `node --check` только на машине
разработчика.

Пути — от `TNS65/`. Статика живёт в `engine/web/` и встраивается в бинарник без
сборщика; JSON и WebSocket отдаёт пакет `engine/internal/webapi` на loopback. Игроку
видны только функциональные названия — «Прорисовка карты», «Граф отношений»,
«сводка»; внутренние код-имена ролей (Паганель, Пила, Ткач) на игровых экранах не
встречаются.

### T-08-02. Веб-сервер на loopback и раздача статики
- **Атомы:** F-04.2, F-11.3.
- **Выдержки атомов:** F-04.2 — слушающий сокет только на loopback; F-11.3 — статика встраивается в бинарник.
- **Зависит от:** T-08-01, T-01-02, T-01-12.
- **Создаётся:** `engine/internal/webapi/{server.go,static.go,routes.go,ws.go,server_test.go}`, `engine/internal/webapi/ROUTES.md`, `engine/web/embed.go`.
- **Правится:** `engine/cmd/tns65/main.go` (старт веб-сервера), `engine/config.yaml` (секция `web`).
- **Писатель:** нет записи в базы; сервер раздаёт статику и JSON, строка доступа — в журнал станка.
- **Шаги:**
  1. Слушать `127.0.0.1:8720`; наружных слушающих сокетов нет — адрес берётся из `config.yaml`, дефолт строго loopback; таблица допустимых значений `host` фиксирована (`127.0.0.1`, `localhost`), иные — ошибка старта.
  2. `engine/web/embed.go` встраивает `engine/web/` через `embed.FS`; статика отдаётся из бинарника, не с диска.
  3. `ROUTES.md` — эталон таблицы маршрутов: метод, путь, тело запроса, ответ, коды ошибок; каждая задача P7, добавляющая маршрут, правит `ROUTES.md` и тест сверки — таблица в файле и реальный роутер совпадают дословно.
  4. Единый контракт ошибок: HTTP-код + тело `{"error":{"code":"…","message":"…"}}`; коды ошибок — константы.
  5. Роутер: статика по путям экранов и JSON-эндпоинты `/api/...`; WS-хаб (`ws.go`): подключение, подписка на топики экранов, рассылка JSON `{"topic":"…","event_type":"…","payload":{…}}`; формат WS-сообщений — в `ROUTES.md`.
  6. Каждый HTTP-запрос пишет строку доступа в журнал станка (`event=web.access`).
  7. Тест: статика отдаётся из embed, `/api/health` отвечает JSON, слушатель не поднимается на не-loopback адресе, таблица маршрутов совпадает с `ROUTES.md`.
- **Проверка:** `cd engine && bash scripts/runtests.sh ./internal/webapi TestServeStatic TestHealth TestLoopbackOnly TestRouteTable` → PASS: статика отдаётся из embed, `/api/health` отдаёт JSON, `net.Listen` на не-loopback адресе отвергнут, маршруты роутера равны `ROUTES.md`; `gofmt -l internal/webapi` → пусто.
- **Исполнитель:** код.

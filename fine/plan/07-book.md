# P6. Книга

Цель волны: живой ход оседает в книгу игрока. Глава — игровой день как рамка: от
пробуждения до сна; пробуждение выковано мастерской заранее и подаётся мгновенно,
первая реплика главы разбирается одним дешёвым вызовом модели, латентность скрыта
в окне чтения. К концу волны станок закрывает главу сном, гонит её через Редактора
и Цензора правок, выпускает дайджест и только после полной обработки показывает
главу в книге — ни текста, ни дайджеста, ни заглушки раньше.

Книга — издательская сторона игры: окно «Моя книга» с четырьмя вкладками,
навигация по содержанию, правки игрока только орфографии и пунктуации, экспорт
главы и книги в Markdown с именами по слагу. Заявка книги — короткое авторское
описание от игрока, критерий отбора, а не план действий; эпилог — единственная
глава чистого авторства игрока, без вмешательства модели; метки пиков — авторская
разметка важных моментов.

Волна жёстко разделяет исполнителей: код закрывает главы, ведёт очередь редактуры,
применяет правки, собирает содержание и экспорт; модель (Редактор) правит
орфографию/пунктуации и пишет дайджест, Цензор бракует непрошедшее автоматически,
слот разбора разбирает первую реплику. Все записи — в оперативную базу мира
`world(<slug>).db`, писатель — ядро; задачи роя отдают результат ядру и в базу
напрямую не пишут.

Пути — от `TNS65/`. Шелл для всех команд: `export PATH="$HOME/.local/go/bin:$PATH"`.

### T-07-02. Утро главы: пробуждение
- **Атомы:** CB-01.
- **Выдержки атомов:** CB-01.2 — пробуждение выковывается заранее, к концу окна 8 часов обязано быть в базе; живая генерация — запасной путь; CB-01.4 — состав: три последних хода предыдущей главы, статы, портрет, положение.

- **Правится:** `engine/internal/db/schema/world/tables.txt`, `engine/internal/db/world_test.go`, `engine/ARCHITECTURE.md` (реестр миграций).
- **Писатель:** `core` — пишет пробуждение в `wakeups` оперативной базы мира; текст пробуждения ковки отдаёт однозадачная задача роя ядру, в базу напрямую не пишет.
- **Шаги:**
  1. Завести таблицу `wakeups(id, chapter_id, text, status CHECK(status IN ('forging','ready')), forged_at, delivered_at)`; `chapter_id` — `UNIQUE`: повторная ковка главы не создаёт вторую запись, а переводит `forging → ready`.
  2. Сессия создаётся только приходом игрока; движок сессий не создаёт, мир не выходит на связь и не начинает первым.
  3.   4. Состав пробуждения: для первой главы книги — из поля «Пролог» анкеты (B-02.4: пролог подаётся при старте книги); для остальных — три последних хода предыдущей главы, статы, портрет, положение; состояние сна наследуется от отхода ко сну; пейзаж и мелкое чувство — по портрету; цель — спровоцировать ответ игрока; крючков нет.
  5. Две ветки открытия: реплика игрока открывает главу и мир отвечает готовым пробуждением; пассивность — таймер 30 с (из config, на подставных часах) внутри сессии, движок подбирает запись по составу и открывает день, ответ игрока становится первой репликой главы.
  6. Таймер действует только при открытии главы; дальнейшие паузы обычные.
- **Проверка:** `cd engine && bash scripts/runtests.sh ./internal/book TestWake` → PASS: без реплики 30 с на подставных часах пробуждение подано из базы; повторный вход не создаёт вторую сессию и вторую запись `wakeups` (UNIQUE); первая глава открывается текстом из Пролога; текст пробуждения не содержит крючков; после закрытия главы в очереди мастерской стоит ковка пробуждения со статусом `forging`; при непрогретой ковке сработал живой запасной путь.
- **Исполнитель:** ядро станка (таймер, очередь, ветки) и модель (ковка текста пробуждения; в тестах — фейковый слот).

### T-07-03. Глубокий разбор первой реплики
- **Атомы:** CB-02.
- **Выдержки атомов:** CB-02.2 — на главу ровно один дешёвый вызов модели; CB-02.4 — результат — JSON с полями «намерение», «план», «предчувствие», «незакрытая тема»; каждое поле несёт цитату, не пересказ; поле ниже порога доверия игнорируется.
- **Зависит от:** T-01-06, T-03-08 (слот на запаске `:5001`), T-05-03, T-07-02, T-02-15.
- **Создаётся:** `engine/internal/book/{deepread.go,deepread_test.go}`, `engine/internal/db/schema/world/0008_book_deepread.sql`.
- **Правится:** `engine/internal/db/schema/world/tables.txt`, `engine/internal/db/world_test.go`, `engine/ARCHITECTURE.md`.
- **Писатель:** `core` — пишет результат разбора в `deep_reads` и разносит поля в факты Ткача и карту игрока Пифии; слот разбора — модель, в базу напрямую не пишет.
- **Шаги:**
  1. Завести таблицу `deep_reads(id, chapter_id, intent_json, plan_json, foreboding_json, open_thread_json, citations_json, raw_json, created_at)`; каждая колонка — `{"value":"…","quote":"…","confidence":0..1}`; `raw_json` хранит полный ответ слота для аудита.
  2. Разбор выполняется один раз на главу — на первую реплику; остальные реплики дают только настроение.
  3. Слот разбора — внешний или встроенный пайплайн станка (до T-03-18 — запаска `:5001`); счётчик вызовов инжектируется (testkit); событие `deepread.call` маркирует вызов разбора (отличим от прочих вызовов слота).
  4. Контракт результата: JSON из четырёх полей, каждое с цитатой и `confidence`; цитата проверяется кодом как подстрока реплики игрока после нормализации (единственная проверяемая форма «не пересказ»); поле с `confidence < deepread.confidence_threshold` (config, по умолчанию 0.6) при разносе в факты игнорируется, но в `deep_reads` хранится; мусорный ответ — политика отказов (00-INDEX).
  5. Латентность скрыта: в ветке мгновенного ответа — окном чтения пробуждения, в ветке пассивного открытия — окном сборки ответа.
  6. Поля выше порога идут в факты Ткача и карту игрока Пифии; после разбора Селектор (T-03-09) может подать крючок по незакрытой теме или запустить событие по настроению; крупное событие — заказ мастерской и срабатывает через главу.
- **Проверка:** `cd engine && bash scripts/runtests.sh ./internal/book TestDeepRead` → PASS: на первую реплику главы счётчик `deepread.call` равен 1, на вторую реплику той же главы — 0; каждое поле результата содержит цитату-подстроку реплики; поле с `confidence=0.5` при пороге 0.6 в разнос не пошло, но сохранилось в `deep_reads`; полный ответ слота есть в `raw_json`.
- **Исполнитель:** модель (разбор; в тестах — фейковый слот) и код (слот, порог доверия, разнос полей).

### T-07-07. Появление глав только после обработки

### T-07-09. Заявка книги
- **Атомы:** CB-10.
- **Выдержки атомов:** CB-10.2 — после нескольких сессий движок формирует предложение заявки по накопленным паттернам; CB-10.4 — три применения: приоритет ночной ковки, зазор в дайджесте, аннотация; CB-10.5 — заявка — критерий отбора, не план действий.
- **Зависит от:** T-01-06, T-02-01, T-05-03, T-07-06, T-07-07 (векторы глав), T-02-07.
- **Создаётся:** `engine/internal/book/{claim.go,claim_test.go}`, `engine/internal/db/schema/world/0009_book_claim.sql`.

- **Писатель:** `core` — пишет заявку в `book_claim` и вектор смысла в `vectors`; предложение заявки отдаёт модель, в базу напрямую не пишет.
- **Шаги:**
  1. Завести таблицу `book_claim(id, text, vector_id, status, created_at)`; заявка — текст (1–3 предложения) плюс вектор смысла.
  2. Заявку пишет игрок — авторство с первой строки; заявку можно пропустить, книга без заявки функционирует.
  3. После трёх и более сессий движок формирует предложение заявки по накопленным паттернам игрока (карта Пифии); игрок утверждает его или правит; исходный синопсис анкеты (T-02-01) — опорная точка первого предложения.
  4. Три применения с числами: приоритет ночной ковки — +30 к приоритету заказов тем заявки; зазор «заявка ↔ накопленная книга» — дрейф числом в дайджесте: `drift = 1 − cos(вектор заявки, центроид векторов глав)`; аннотация готовой книги — переработка заявки вместе с фактическим содержанием (сборка — T-07-12).
  5. Граница твёрдая: заявка — критерий отбора, а не план действий; внутри глав она ничего не выбирает и не правит; Селектор и Пила не ведут игрока к заявке — тест `go list -deps` подтверждает, что `selector` и `saw` не импортируют пакет `book`.
- **Проверка:** `cd engine && bash scripts/runtests.sh ./internal/book TestClaim` → PASS: книга создаётся и играется без заявки; при наличии заявки хранятся текст и вектор (`dim=1024`); дрейф `1 − cos(заявка, центроид)` вычислен и отличен от нуля; предложение заявки формируется после трёх сессий; `go list -deps ./internal/selector` не содержит `internal/book`.
- **Исполнитель:** код (хранение, дрейф) и модель (предложение заявки; в тестах — фейковый слот).

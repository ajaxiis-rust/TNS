# P11. Канон, библиотека книг, цензор и мастер первого запуска

Статус: план на согласование, 2026-11-02.
Норма: этот файл + `fine/04-spec`; при расхождении действует атом спеки.
Основание: решения владельца от 2026-11-02 (раздел 1).

Волна P11 закрывает пять разрывов, найденных при обсуждении:

1. Канон анкеты мал: 10 жанров, 11 строёв, 4 экономики. Станок обещает
   потребителей (Паганель, Пифия, социальный граф, экономика), но списки
   не покрывают книжные полки.
2. Книги нельзя положить на полку до рождения мира: `/api/mcp/import`
   требует слаг мира, а ковка книги `swarm-task forge-book` не реализована —
   задача завершается кодом 2, книга получает `status=error`.
3. Цензор при ковке включён, но словарь — заглушка из семи служебных слов
   (`и, в, на, с, не, что, как`). В таком виде он отклонит любой русский
   текст. Рейтинг `censorship` хранится и не читается. Отказ модели
   (провайдер запретил сцену) не отличается от нарушения словаря.
4. Нет мастера первого запуска и нет `llama-server` в поставке: игрок
   не может поднять станцию сам.
5. Из книги не извлекается карта героев: имена, описания, характеры и роли
   не попадают никуда. Механика почти отработана в devForge, но там она
   решает обратную задачу — убрать имена при анонимизации.

## 2. Что уже сделано и входит в этот коммит

Перечисленное лежит в рабочем дереве, проверено тестами и браузером,
коммитится вместе с планом:

- атлас: форма рождения с жанрами-чипами, слагом, счётчиком предложений,
  аккумуляцией ошибок по полям;
- настройки: карточки моделей с установкой и прогрессом внутри карточки,
  статус моделей, роли с подсказками, свёрнутые технические блоки;
- `GET /api/atlas/birth` — канонические списки для формы;
- `GET /api/settings/models/status` — статус установки и загрузки;
- контракт ошибок с полями (`error.fields`);
- netgate: поддомены `*.huggingface.co`, `*.hf.co`, снятие кавычек;
- загрузка netgate при старте ядра;
- список языков мира в данных анкеты.

Не сделано и является предметом P11: полка, реестр книг, задача
`forge-book`, привязка фанфика, цензор, мастер, `llama-server`.

## 4. Канон: 18 строёв и 8 экономик

Строи (18): нет, феодализм, демократия, анархия, теократия, коммунизм,
капитализм, социализм, трайбализм, рабовладение, меркантилизм,
абсолютная монархия, конституционная монархия, олигархия, технократия,
корпоратократия, военная диктатура, кастовая система.

Экономики (8): золотой стандарт, серебряная экономика, бартер,
командная экономика, фиатные деньги, кредитная экономика,
ресурсная экономика, гильдейская.

### 4.1. Веса сословий (W1)

`estateWeight` — коэффициент 0.1–1.0, записывается в каждую из 96 карточек
полем `weight`. Это не налог, не квота и не частота: коэффициент влияния
сословия при данном строе. Сегодня его никто не читает; он заготовлен под
социальный граф и экономику. Если строки для строя нет, вес = 1.0 и строй
становится невидимым — поэтому таблица обязательна.

Существующие 11 строк не меняются. Новые 7:

| строй | военный | купец | аристократ | духовенство | ремесленник | крестьянин |
|---|---|---|---|---|---|---|
| абсолютная монархия | 0.8 | 0.4 | 1.0 | 0.7 | 0.6 | 0.9 |
| конституционная монархия | 0.7 | 0.9 | 0.7 | 0.4 | 0.8 | 0.6 |
| олигархия | 0.5 | 1.0 | 0.6 | 0.2 | 0.6 | 0.5 |
| технократия | 0.6 | 0.6 | 0.3 | 0.2 | 0.9 | 0.4 |
| корпоратократия | 0.4 | 1.0 | 0.3 | 0.1 | 0.7 | 0.4 |
| военная диктатура | 1.0 | 0.4 | 0.5 | 0.3 | 0.6 | 0.7 |
| кастовая система | 0.8 | 0.6 | 0.9 | 1.0 | 0.5 | 0.3 |

Обоснование кратко: в абсолютной монархии максимум у аристократа и высокая
доля крестьянства; в конституционной растёт купец; в олигархии и
корпоратократии — купец; в технократии — ремесленник (в шести сословиях нет
инженера, это ближайшее); в военной диктатуре — военный; в кастовой —
духовенство и аристократ, низ у крестьянина.

Ограничения:

- сословий шесть; добавлять седьмое («инженер/учёный») нельзя без смены
  B-05 (96 → 112 карточек). В P11 не делаем.
- веса замораживаются в карточке при рождении: правка таблицы улучшает
  только новые миры. Это согласуется с «мир после рождения не редактируется».

| бартер | 0 | 0 | 0 | 0 |
| командная экономика | 2 | 0 | 1 | 1 |
| фиатные деньги | 2 | 2 | 0 | 1 |

## 5. Три базы, полка и книга-раздел

### 5.1. Раскладка

```
base.ru.db                     # поставка, только чтение
world_db/
  models/                      # модели (MD-09)
  library/                     # НОВОЕ: глобальная полка книг
    library.json               # манифест полки
    books/<id>/<файл>          # сырьё txt/fb2
  worlds/<slug>/
    world.db                   # оперативная база мира
    literary.db                # литературная база мира
    sources/                   # сырьё, привязанное к миру (MCP)
```

`world_db/library/` — сосед `worlds/`; `birth.List` сканирует только
`worlds/*`, поэтому полка миром не считается.

### 5.2. Манифест полки

`library.json` — массив книг:

```json
{
  "id": "hp-1997",
  "name": "Гарри Поттер и философский камень",
  "author": "Дж. К. Роулинг",
  "format": "fb2",
  "lang": "ru",
  "genres": ["фэнтези", "подростковый"],
  "rating": "16+",
  "chapters": 17,
  "bytes": 1234567,
  "sha256": "…",
  "status": "ready",
  "progress": 1.0,
  "created_at": "2026-11-02T10:00:00Z"
}
```

Статусы: `imported` (файл лёг), `parsing`, `queued`, `forging`, `ready`,
`error`, `player` (книга игрока, только в `literary.db`).

### 5.3. Реестр книг в literary.db

Миграция `engine/internal/db/schema/literary/0004_book.sql`:

```sql
CREATE TABLE book (
    id INTEGER PRIMARY KEY,
    shelf_id TEXT NOT NULL DEFAULT '',
    name TEXT NOT NULL,
    lang TEXT NOT NULL,
    genres TEXT NOT NULL DEFAULT '',
    rating TEXT NOT NULL DEFAULT '',
    chapters INTEGER NOT NULL DEFAULT 0,
    status TEXT NOT NULL,
    created_at TEXT NOT NULL
);

ALTER TABLE bank_pool ADD COLUMN book_id INTEGER REFERENCES book(id);
```

Почему так: сегодня книга опознаётся только строкой `origin`. Реестр даёт
выпадающий список, привязку и фильтр «свои записи» без разбора строк.
`book_id IS NULL` — старые записи и сид; миграция старых миров не нужна.

### 5.4. Книга игрока

Строка `book` со `status='player'` создаётся при рождении мира; имя — заголовок
мира. Осевшие сцены игрока (`sediment_scene` → переплавка → `bank_pool`)
получают `book_id` этой книги. Это и есть «своя книга-раздел» без переделки
станка.

### 5.5. Привязка фанфика

- В анкете `source_book` — id книги полки. Обязателен ровно при жанре
  «фанфик»; при отсутствии галочки поле пустое (15-е поле, необязательное).
- При рождении в `world_meta` пишутся `source_book_id` и `source_book_name`.
- Если фанфик выбран, а книги нет — форма не отправляется: модалка требует
  выбрать книгу или импортировать её.
- Модалка берёт список из двух источников: книги этого мира (если мир уже
  есть) и книги полки. У нового мира `literary.db` ещё нет, поэтому основной
  список — полка; это глобальный список, `literary.db` — его копия в мире.
- После рождения книги менять нельзя (мир заморожен). Добавить ещё одну
  книгу в существующий мир можно как материал, но привязка фанфика
  остаётся той, что записана при рождении.

### 5.6. Ковка книги

Сегодня: `/api/mcp/forge` запускает `swarm-task forge-book`, а
`runSwarmTask` в `cmd/tns65/main.go` принимает только `forge-card` и
возвращает 2. Нужно реализовать.

Поток одной книги:

1. Разбор входа (`workshop.ParseBookInput`) → `ParsedBook` с чанками.
2. Для каждого чанка: `origin = "forge-book:<book_id>:<n>"`,
   `ForgeMaterial{Kind:"routine", Lang, Tags}` → `ForgeComposition`
   (классификация семьи кодом + слот `compose`).
3. Делексификация, проверка фактов, цензор, запись `bank_pool` с `book_id`.
4. Вектор чанка в `vectors` (`owner_table='bank_pool'`) — для литературного
   отбора и гороскопа.
5. Прогресс в `library.json`/`sources.json`, строки `forge_log`, идемпотентность
   по `origin` (повторный запуск не дублирует).

Зависимости ковки: слот `compose` (`:5001`) и эмбеддер (`:5002`). Оба
локальные; внешний провайдер для книг не нужен.

### 5.7. Синхронно или фоном

- Фанфик: после рождения, отдельным шагом с прогрессом, до первого хода.
  Внутрь рождения не ставим: T-02-14 запрещает внешние вызовы, а ковка
  требует слота.
- Остальные книги: фоном после рождения.
- Если модели нет: мир открывается на сиде с предупреждением, ковка
  повторяется позже. Игрок видит «язык книги ещё готовится», а не поломку.

### 5.8. Шум фандома

`turn/composition.go` читает `bank_pool`; для мира с `source_book_id`
записи привязанной книги получают множитель 3.0 в скоринге. Сид и другие
книги остаются фоном. Константа `fanficBookBoost = 3.0` в `turn/composition.go`.
Без множителя 1121 универсальный нарратив перебивает фандом.

### 5.9. Карта книги: имена, описания, характеры, роли

Каждая книга на полке проходит извлечение карты действующих лиц — и книга
фанфика, и любая другая. Это обратная задача по отношению к devForge:
devForge имена **убирает** (анонимизация), нам они нужны для NPC. Язык,
описания, характеры и роли — материал для пустых карточек и для канонных
героев фанфика.

#### Что переиспользуем из devForge (аудит 2026-11-02)

| Механика devForge | Где | Что берём |
|---|---|---|
| `src_verses` / `src_characters` / `src_mentions` | `internal/ingest` | карта «кто в каком куске упомянут»; из неё first/last и плотность |
| `namescan` — кандидаты имён по заглавным буквам, стоп-листы | `internal/namescan` | каркас скана; списки нужны свои на каждый язык |
| `characters.json` — id, canon, ru, aliases, sig | `internal/lexicon` | слияние алиасов, замена по длинному алиасу раньше короткого |
| `deidentify` — регулярные замены по границам слов | `internal/deidentify` | делексификация текста банка (не карты) |
| `archetypes` + `classify` — 14 семей по ключевым словам | `internal/archetypes`, `classify` | уже есть в движке (`structural`), карту не дублируем |
| батчи по 5 и журнал «модель + версия словаря» | `internal/cook`, `archetypes` | устойчивость к обрыву, докатка без повторных вызовов |
| `arch_llm` — журнал происхождения ярлыков | `internal/archetypes` | ключ кэша для извлечения карты |
| `translate` — имена и биты, строгий оракул токенов | `internal/translate` | позже, если книга не на языке мира |
| `verify` — чтение баз как движок | `internal/verify` | проверка после ковки |

Чего в devForge нет: описаний внешности, черт характера и ролей по отрезкам.
`sig` там — статичный ярлык на всю книгу (`patriarch`, `king`), для Снейпа
недостаточный. Эти три вещи проектируем заново.

#### Схема (literary.db, миграция 0005)

```sql
CREATE TABLE book_chunk (
    id INTEGER PRIMARY KEY,
    book_id INTEGER NOT NULL REFERENCES book(id),
    ord INTEGER NOT NULL,
    chapter TEXT NOT NULL DEFAULT '',
    text_hash TEXT NOT NULL,
    UNIQUE (book_id, ord)
);

CREATE TABLE book_character (
    id INTEGER PRIMARY KEY,
    book_id INTEGER NOT NULL REFERENCES book(id),
    name TEXT NOT NULL,
    aliases TEXT NOT NULL DEFAULT '[]',
    appearance TEXT NOT NULL DEFAULT '',
    description TEXT NOT NULL DEFAULT '',
    traits TEXT NOT NULL DEFAULT '[]',
    confidence REAL NOT NULL DEFAULT 0,
    first_chunk INTEGER NOT NULL DEFAULT 0,
    last_chunk INTEGER NOT NULL DEFAULT 0,
    mentions INTEGER NOT NULL DEFAULT 0,
    status TEXT NOT NULL DEFAULT 'candidate',
    created_at TEXT NOT NULL
);

CREATE TABLE book_character_mention (
    character_id INTEGER NOT NULL REFERENCES book_character(id),
    chunk_id INTEGER NOT NULL REFERENCES book_chunk(id),
    count INTEGER NOT NULL,
    PRIMARY KEY (character_id, chunk_id)
);

CREATE TABLE book_character_role (
    id INTEGER PRIMARY KEY,
    character_id INTEGER NOT NULL REFERENCES book_character(id),
    from_chunk INTEGER NOT NULL,
    to_chunk INTEGER NOT NULL,
    role TEXT NOT NULL,
    confidence REAL NOT NULL DEFAULT 0,
    evidence TEXT NOT NULL DEFAULT ''
);
```

Текст кусков не дублируется: `book_chunk` хранит номер, главу и хеш;
извлечение заново разбирает файл полки тем же чанкером. Сырьё остаётся
файлом (B-03.7), в базе только выкованное.

#### Конвейер

1. **Кандидаты без LLM.** Заглавные слова и устойчивые пары, частота,
   атрибуция реплик («сказал…», «said…»), стоп-листы служебных слов и
   топонимов. Для русского заглавная буква — слабый признак, поэтому
   дополнительно лемматизатор и частота; профиль языка — данные, а не код.
2. **Слияние алиасов.** Общие токены и сокращения: «Северус Снейп»,
   «Снейп», «профессор Снейп» → одна запись. Длинный алиас проверяется
   раньше короткого.
3. **Карта упоминаний.** Для каждого кандидата — счётчик по кускам; first/last
   и плотность отсеивают случайные имена.
4. **Подтверждение и описание (роль `cast`, локальный слот).** Для топ-K по
   упоминаниям (по умолчанию 24) — до трёх фрагментов (первый, средний,
   последний) и строгий JSON:
   `{name, aliases, appearance, description, traits[], role_segments[],
   confidence}`. Роли — из закрытого списка; каждый отрезок несёт
   `from_chunk`, `to_chunk`, `role`, `confidence`, цитату-основание.
   Мусор или отказ модели → запись остаётся кандидатом с пустым описанием;
   выдумывать нельзя.
5. **Роли по отрезкам.** Пример: Снейп — `антагонист` куски 1–6, `союзник`
   куски 7–17. Роль необязательна: пусто — нормальное состояние. Список:
   протагонист, антагонист, наставник, союзник, соперник, трикстер, жертва,
   власть, фон.
6. **Запись и журнал.** `forge_log kind='cast'` с моделью и версией промпта;
   повтор по тем же `text_hash` не зовёт слот. Батчи по 5 кусков.
7. **Промоушен.** Мир-фанфик: топ-16 подтверждённых попадают в
   `world.db.characters` как именные NPC (психотип и сословие — по правилам
   пачки, описание — из книги). Пачка остаётся 96 карточек: именные герои —
   отдельный слой, как карточки доукомплектации. Остальные книги: карта
   живёт в `literary.db`, описание подставляется в пустую карточку по имени
   (LT-06.2), промоушен — по требованию, когда игрок называет героя.

#### Режимы и стоимость

- **quick** — кандидаты, алиасы, упоминания, без LLM. Секунды на книгу.
- **full** — описания, характеры, роли. До 24 персонажей × 3 фрагмента на
  локальном слоте; на 3B это десятки минут на книгу.
- Фанфик: quick синхронно до первого хода, full — фоном. Остальные книги:
  quick и full фоном.
- Потолки (K персонажей, число фрагментов, длина фрагмента) — данные
  конфига, а не константы в коде.

#### Оптимизация против devForge

- `namescan` английский и библейский: списки вынести в профили языка.
- Ручной аудит `characters.json` заменяется автоподтверждением с порогом
  уверенности; ручная правка остаётся возможной.
- Делексификация и извлечение карты разведены: карта читает сырой текст,
  банк — очищенный.
- Кэш по `text_hash` + модель + версия промпта, иначе повторная ковка
  оплачивается заново.

## 6. Цензор, рейтинг и отказы

### 6.1. Что есть сейчас

- `censor.Check(text, lang)` — лемматизация + `packs/<lang>/stoplist.txt`;
  попадание → запись не пишется (`ErrCensorReject`).
- Словарь `engine/packs/ru/stoplist.txt` — 7 служебных слов. Включённый
  цензор отклонит любой русский текст. До ковки книг словарь обязан стать
  настоящим.
- Рейтинг `censorship` (16+/18+) хранится в `world_meta`, объявлен
  потребителем в `consumers.json`, но не читается.
- Отказ модели не детектируется: он попадает в банк как «текст» или роняет
  ковку.

### 6.2. Целевая механика

1. Два словаря пакета: `stoplist.txt` — базовый (нельзя никогда),
   `stoplist_16.txt` — дополнительный для 16+. 18+ использует только базовый.
2. `refusals.txt` (ru + en) и детектор по форме ответа, не по одному слову:
   короткий ответ (≤ 600 знаков), мета-маркеры («как ИИ», «языковая модель»,
   «не могу помочь с этим запросом», «против политики», «извините, но я не
   могу»), проверка первых 300 знаков. Реплика героя «я не могу тебе помочь»
   отказом не считается.
3. Рейтинг при ковке: 18+ → внешние провайдеры для мира исключены, только
   локальный слот; 16+ → базовый словарь + `stoplist_16.txt`.
4. Лестница повторов: (1) та же сцена с художественной рамкой и рейтингом в
   системном промпте; (2) смена формы промпта, трудная часть уходит за кадр;
   (3) переключение слота на локальный; (4) деградация — сцена без
   выкованного фрагмента, отказ в журнал. Ход не отменяется.
5. Два прохода для ролей прозы: сначала сухие факты «что происходит», затем
   проза. Отказы чаще бьют по прозе; факты выживают.
6. Журнал: `forge_log` (`kind='censor'`, `task='refusal'`) с провайдером и
   ролью; счётчик отказов на дашборде MCP.

Честная граница: политику внешнего провайдера промптом не отменить.
Станция может маршрутизировать, повторять и деградировать.

### 6.3. Содержимое словаря

Словарь — отдельная содержательная работа. Базовый список: обсценная лексика
и оскорбительные ярлыки. 16+: маркеры явного насилия и секса. Насилие как
таковое не запрещается: 18+ его разрешает. Список готовится отдельно и
утверждается владельцем; в план входит механизм, а не готовый перечень.

## 7. Мастер первого запуска и модели

### 7.1. Сценарий

| Шаг | Что видит игрок | Механика |
|---|---|---|
| 0 | «Проверяю станцию» | есть ли `llama-server`, свободны ли `:5001`/`:5002`, есть ли модели |
| 1 | Три карточки BGE-M3 с объяснением | скачивание, прогресс в карточке, запуск `:5002`, проверка вектора |
| 2 | «Соберите библиотеку» (необязательно) | полка: импорт txt/fb2, список книг, статусы |
| 3 | «Создайте мир» | анкета: заголовок, синопсис, строй, жанры, рейтинг |
| 4 | «Готово» | переход в чат; повторный запуск пропускает пройденные шаги |

Состояние мастера — `state/first-run.json`, идемпотентно. Пройденные шаги
не переспрашиваются; настройки потом редактируются в «Настройках».

### 7.2. BGE-M3: три варианта

| Файл | Размер | Когда предлагать |
|---|---|---|
| `bge-m3-Q4_K_M.gguf` | 438 МБ | мало RAM (< 8 ГБ) |
| `bge-m3-Q8_0.gguf` | 634 МБ | баланс, рекомендуется по умолчанию |
| `bge-m3-F16.gguf` | 1,16 ГБ | RAM ≥ 16 ГБ, максимальное качество |

Источник: `gpustack/bge-m3-GGUF` (MIT, dim 1024). Флаги сервера:
`--model <path> --host 127.0.0.1 --port 5002 --embeddings --pooling cls
-c 8192 --threads N`. После старта — проверка: косинус двух близких фраз
выше косинуса далёких; иначе понятная ошибка «пулинг не тот».

### 7.3. Поставка `llama-server`

Релизные бинарники собирает GitHub Actions (матрица linux/windows/macos),
либо `engine/scripts/install-llama.sh` скачивает закреплённый релиз llama.cpp
с GitHub и проверяет sha256. Оба пути допустимы; для P11 делаем скрипт,
релиз — отдельной задачей. Бинарник кладётся в `bin/` поставки, не в PATH.

### 7.4. Супервизор

`internal/supervisor` расширяется до жизненного цикла процессов:

- запуск с аргументами модели и портом;
- health-check (`/health`), таймаут, повтор;
- перезапуск с backoff, счётчик падений;
- логи в `state/journal/llama.log`;
- проверка занятости порта до старта;
- остановка при выходе ядра;
- смена модели: стоп → старт → health, откат на прежнюю при провале.

Тесты — с фейковым сервером (уже есть приём в `supervisor`).

## 10. Риски

1. **Словарь.** Плохой список даёт ложные отказы и убивает прозу. Мера:
   тест на обычной прозе, счётчик срабатываний, отдельное утверждение списка.
2. **Права на книги.** Полка хранит пользовательские файлы; станок их не
   распространяет. Ответственность за содержимое — на владельце станции.
3. **Отказы провайдеров.** Промпт снижает частоту, но не отменяет политику.
   Мера: маршрутизация на локальный слот и деградация без отказа хода.
4. **RAM.** BGE-M3 F16 и генерация вместе могут не влезть. Мера: рекомендация
   по RAM и предупреждение до скачивания.
5. **Старые миры.** Миграция 0004 добавляет `book_id` NULL; старые записи
   читаются как раньше.
6. **Долгая ковка книги.** Синхронный фанфик может идти минуты. Мера:
   прогресс, возможность продолжить на сиде, повтор позже.
7. **Зависимость ковки от `:5002`.** Векторы книги требуют эмбеддера. Мера:
   понятная ошибка и повтор, без порчи `literary.db`.
8. **Windows.** `llama-server` и пути к моделям. Мера: релизная матрица и
   проверка на Windows перед P11.5.
9. **Качество карты на локальной 3B.** Имена и упоминания даёт код, описания —
   модель. Мера: порог уверенности, пустое описание вместо выдумки, ручная
   правка карты.
10. **Спойлеры.** Роль по отрезкам раскрывает поворот (Снейп — скрытый герой).
    Мера: игроку роль не показывать; карта служит станку.
11. **Время полной карты.** 24 персонажа × 3 фрагмента — десятки минут.
    Мера: quick сначала, full фоном, ограничение K в конфиге.

## 11. Открытые вопросы

1. Полка: имя каталога `world_db/library/` — принимается?
2. Словарь: базовый список готовлю я и отдаю на утверждение, или владелец
   даёт свой перечень?
3. Фанфик без модели: разрешать «продолжить на сиде» с предупреждением или
   блокировать первый ход до готовности книги? Рекомендую разрешать.
4. BGE-M3 по умолчанию: Q8_0 (634 МБ) как баланс, Q4_K_M для машин < 8 ГБ,
   F16 для ≥ 16 ГБ — подтверждается?
5. Шаблоны: книга пишет только `bank_pool` + векторы, `lit_template`
   остаётся за сидом и стилевой ковкой — подтверждается?
6. Карта: K = 24 персонажа на книгу и топ-16 промоушена в мир-фанфик —
   подтверждается?
7. Роли по отрезкам: закрытый список из девяти (протагонист, антагонист,
   наставник, союзник, соперник, трикстер, жертва, власть, фон) — принимается?
8. Карта хранится на языке книги; перевод на язык мира оставляем на потом?

## 12. Что не входит в P11

- четвёртая база и общий выкованный банк;
- седьмое сословие (96 → 112 карточек);
- потоковая докачка и установка, переживающая закрытие вкладки;
- многопровайдерный каталог моделей;
- перенос активного мира между перезапусками;
- публикация релиза `llama-server` (P11 делает скрипт установки);
- перевод карты книги на язык мира;
- ручной редактор карты (правится файлом/API, отдельного экрана нет).

# P12. Скачивание моделей, шаг llama.cpp в визарде и живой UI станции

Статус: план на согласование, 2026-11-03.
Норма: этот файл + `fine/04-spec` (MD-08, MD-09, UI-08); при расхождении действует атом спеки.
Основание: ручной тестовый запуск владельца 2026-11-03 (TNS-GAME, Firefox) и разбор
кода по его замечаниям; вилки закрываются решениями владельца из §1.

## 0. Разрывы, найденные ручным запуском

1. **Скачивание однопоточное и живёт в RAM.** `defaultFetchModelFile`
   (`internal/webapi/handlers_settings.go:979`) — один GET, чтение буфером 32 КБ,
   файл целиком копится в `bytes.Buffer`, затем sha256 по памяти и запись на диск
   из памяти. Пик памяти ≈ двойной размер файла (weaver 2 ГБ → >4 ГБ RAM при
   7,2 ГБ на машине). Ни Range-чанков, ни докачки, ни журнала.
2. **Имена файлов моделей искажаются.** Установленный файл переименовывается в
   `current.bin`/`previous.bin` (`installModelFile`), исходное имя
   (`bge-m3-Q4_K_M.gguf`) теряется. Владелец требует: имя файла сохраняется
   исходным, без «импорта» и перевода в другие форматы и названия.
3. **В визарде нет шага установки llama.cpp.** Скрипт поставки есть
   (`scripts/install-llama.sh`, T-12-18), супервизор умеет жизненный цикл
   (T-12-19), `embedserver.Spec().Child()` собирает конфиг ребёнка — но в
   визарде шага установки нет, продакшн-код ребёнка не запускает,
   `config.yaml` обоих экземпляров держит `children: []`, в TNS-GAME каталог
   `bin/` отсутствует. Рождение мира падает на шаге `anchor`: эмбеддер `:5002`
   не поднят.
4. **UI не перечитывает состояние.** Карточка модели в визарде статична:
   `renderWizardModels` рисует «Не установлена»/«Установить», не спрашивая
   статус; после ручного удаления моделей визард (шаги 0–2 отмечены
   пройденными) открывается сразу на «Мир», вернуться к моделям нельзя.
5. **Создание мира из визарда невозможно.** `onWizardWorldSubmit`
   (`web/static/app.js:3163`) не отправляет `slug`, `birth.Validate` требует
   его (`internal/birth/ancketa.go:113`) — каждый POST `/api/atlas/worlds/birth`
   из визарда возвращает 400 «slug: пустой слаг» — воспроизведено curl на
   живом экземпляре; все попытки рождения из визарда в журнале движка — 400.
6. **Кнопки «задумчивые».** Каждый GET/PUT `/api/first-run(/step)` идёт через
   `readModelStatuses → modelIntegrityOK` — полный `os.ReadFile` каждого
   `current.bin` + sha256 (2,4 ГБ на машине владельца на каждый клик; после
   ручного удаления моделей тот же роут отвечает за 0,6–2 мс). Сверху
   `wizardNext` переключает экран только после ответа сервера, возврата назад
   нет (степпер не кликабелен, кнопки «Назад» нет).
7. **Удаления модели нет.** Маршруты только install/status/rollback
   (`internal/webapi/routes.go:106–108`); битую модель владелец удалял руками
   (`rm -rf world_db/models/`). Карточка установленной модели обязана менять
   «Установить» на «Удалить».
8. **Тексты.** «…по памяти станка…» (`web/wizard.html:134`, `i18n.js:330`),
   сленг «станок/станция» в интерфейсных строках, «Родить мир»
   (`atlas.birth.submit`, `i18n.js:74`) — владелец просит «Создать» для мира.

## 1. Решения владельца (2026-11-03)

| № | Решение | Следствие |

| 2 | Скачивание пишет сразу в файлы, RAM не копит | потоковая запись, докачка с позиции, sha256 потоком |
| 3 | Имена файлов моделей — исходные, без переименования и смены формата | `world_db/models/<роль>/<имя-из-HF>.gguf` + `manifest.json` |
| 4 | В визарде обязательна установка llama.cpp | блок «Движок» в шаге 0 (нумерация шагов 0–4 не меняется): кнопка установки (скрипт T-12-18) + запуск `:5002` |
| 5 | Перечитывание моделей и окружения обязательно в визарде и во всём UI | опрос статуса и станции на интервале, мгновенные переключения шагов, степпер кликабелен, «Назад» |
| 6 | Обработка книги и рождение требуют и векторизации, и локальной модели | после установки модели визард поднимает ребёнка и показывает живой статус портов |

| 8 | «Создать мир» вместо «Родить мир»; без сленга «станок» в UI | правки i18n: компьютер, характеристики, создание |
| 9 | Перед установкой llama.cpp — обнаружение уже установленного:

## 2. Контракты волны

- **Манифест модели** `world_db/models/<роль>/manifest.json`:
  `{"role","model_ref","source","file","sha256","size","installed_at","previous"}`;
  `file` — исходное имя файла из URL; `previous` — имя прежнего файла для
  откката (файл не переименовывается, меняется указатель).
- **Загрузчик**: `func FetchToFile(ctx, source, destDir string, workers int, progress func(Progress)) (FetchResult, error)`;
  `Progress{Bytes, Total int64, MBps float64, Workers, Retries int}`;
  `FetchResult{Path string, SHA256 string, Size int64, MBps float64}`. Нет
  `Accept-Ranges` → одно соединение с потоковой записью в файл, без докачки
  (повтор с нуля); память и журнал работают в обоих режимах. Частичные
  отрезки лежат по одному файлу `<имя>.part/<i>` (докачка отрезка — от его
  размера); по завершении отрезки сливаются в `<имя>` одним проходом, sha256
  считается при слиянии.
- **Роуты**: `DELETE /api/settings/models/delete` (тело `{"role"}` →
  `{"status":"ok","removed":["…"]}`); `POST /api/settings/llama/install` →
  `{"installed":true,"path","version","source"}` (`source`:
  `detect|download` — находить раньше, качать при пустом результате);
  `GET /api/settings/models/status`
  получает `models[]` (установленные, с `file`), `?verify=1` добавляет
  `integrity_ok` с полным sha256 по требованию.
- **Станция**: `GET /api/first-run` расширяется полем
  `station.children: [{"name","port","ready"}]` — визард и настройки рисуют
  живое состояние окружения.
- **Обнаружение llama.cpp** (до скачивания): config.yaml — новое поле
  `llm.llama_server_path` (пусто — автоопределение). Порядок: значение из
  конфига → `bin/llama-server` экземпляра → `exec.LookPath("llama-server")`
  → типовые пути сборки (`~/llama.cpp/build/bin/`, `~/src/llama.cpp/build/bin/`,
  `/opt/llama.cpp/build/bin/`, `~/.local/bin/`, `/usr/local/bin/`). Кандидат
  валиден, когда файл существует, исполним и отвечает на `--version`
  (тайм-аут 5 с). Роуты: `GET /api/settings/llama/detect` →
  `{"found","path","version","source","searched":[…]}` (`source`:
  `config|instance|path|candidates`); `POST /api/settings/llama/detect`
  (тело `{"path"}`) — проверка ручного пути и запись в
  `llm.llama_server_path` (пустой путь очищает поле). `POST
  /api/settings/llama/install` начинает с того же обнаружения: найдено — путь
  записывается, ответ без сети. `station.llama_server` в `/api/first-run`
  несёт решённый путь и версию вместо буля.
- **Поиск по диску**: `POST /api/settings/llama/scan` — ограниченный `find`
  по домашнему каталогу (`-maxdepth 5 -type f -name llama-server`,
  тайм-аут 15 с), выполняется в фоне, результат — список путей для ручного
  выбора; полный обход диска не делается (медленно и шумно по правам).
- **Журнал**: события `model.download.start|done|fail` (url, cdn_host, bytes,
  mbps, workers, retries), `model.deleted`, `llama.installed` (path, version,
  source) — в штатный журнал движка, построчно JSON, как все события.

### T-13-01. Загрузчик Range-чанками в файл
- **Атомы:** MD-09 (загрузка моделей), MD-08.2 (прогресс).
- **Выдержки атомов:** MD-09: «Модели скачиваются с HF напрямую по исходящему
  соединению в каталог world_db/models/», «Штатный канал скачивания — раздел
  менеджера моделей». MD-08: «Менеджер показывает прогресс загрузки».
- **Зависит от:** пусто.
- **Читать:** `fine/plan/13-model-download-wizard.md` (этот файл), §2.
- **Создаётся:** `engine/internal/models/fetch.go`, `engine/internal/models/fetch_test.go`.
- **Правится:** нет (`netgate.Client` уже экспортирован, переиспользуется).
- **Писатель:** нет записи (файлы вне баз).
- **Шаги:**
  1. Проба поддержки докачки: GET с `Range: bytes=0-0`, разбор
     `Accept-Ranges` и `Content-Range` (итоговый размер).
  2. Разбить размер на `workers` отрезков (по умолчанию 4, потолок 8);
     каждый отрезок пишется в свой частичный файл `<имя>.part/<i>` — один
     файл на отрезок: по единому файлу нельзя отличить скачанные байты
     от дыр между ними, размер частичного файла и есть прогресс отрезка.
  3. Докачка: существующий частичный файл продолжается запросом `Range`
     от позиции «размер части» (только при `Accept-Ranges`).
  4. По завершении всех отрезков — слияние частичных файлов в `<имя>`
     одним проходом; sha256 считается в этом же проходе, частичные
     файлы удаляются.
  5. Ретраи: 3 попытки на отрезок с паузой 1/2/4 с; после исчерпания — ошибка.
  6. Прогресс: атомарный счётчик байт; колбэк не чаще 4 раз в секунду, с МБ/с.
  7. События журнала `model.download.start|done|fail` с url, хостом CDN,
     размером, МБ/с, числом воркеров и ретраев.
- **Проверка:** `cd engine && go test ./internal/models -run TestFetch -count=1`
  — httptest-сервер с поддержкой и без поддержки Range, обрыв соединения
  на середине отрезка, докачка с позиции размера части; все PASS.
- **Документы:** нет.
- **Исполнитель:** код.

## 5. Риски

- **GitHub в белом списке netgate** (T-13-06): расширение списка хостов —
  решение безопасности; до согласования шаг llama.cpp остаётся ручным
  скриптом, визард показывает подсказку вместо кнопки. Скрипт поставки —
  bash; на Windows шаг показывает ту же подсказку (PowerShell-вариант
  поставки — вне волны).
  Решение принято 2026-11-03: открываем `github.com` +
  `objects.githubusercontent.com` (визард скачивает сам после того, как
  обнаружение не нашло установленную копию; владелец уведомлён до старта
  T-13-06 и не возразил).
- **Чужая сборка llama.cpp** (обнаруженный по пути бинарник): версия или
  сборка может не поднять выбранную модель. Проверка `--version` при
  обнаружении отсекает нерабочий бинарник, версия видна в блоке «Движок»;
  при отказе старта ребёнка кнопка установки ставит закреплённый релиз
  в `bin/` и решённый путь перезаписывается.
- **CDN без Accept-Ranges**: запасной режим — одно соединение с потоковой
  записью в файл (RAM не копится, sha256 и журнал работают); докачка в этом
  режиме невозможна по протоколу — повтор начинается с нуля. На CDN HF
  диапазоны поддерживаются, ветка срабатывает только на прокси/зеркале.
- **Старая раскладка current.bin**: два формата манифеста читаются вместе;
  автопереименование не делаем (владелец удалил модели руками, на живых
  экземплярах конфликтов нет).
- **Диск и память**: потолок воркеров 8, буфер чтения ≤ 1 МБ на воркер;
  освобождение RAM обязательно (замер в тесте T-13-01).

## 6. Что не входит в P12

- Параллельная загрузка нескольких ролей одновременно (одна роль — один
  загрузчик; очередь ролей — позже).
- Выбор GPU/CUDA-сборки llama.cpp (поставляется CPU-релиз b12063; GPU —
  отдельное решение владельца).
- Модели генерации в визарде как обязательный шаг: карточки ролей weaver/
  pythia доступны в «Настройках»; визард показывает подсказку, что для
  полного конвейера книги нужна и модель генерации.

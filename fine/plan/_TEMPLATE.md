# Формат задачи

Одна задача — один атомарный кусок работы. Агент-исполнитель читает задачу
целиком и не додумывает недостающее; если чего-то нет — задача не готова (DoR).

```markdown
### T-01-04. DDL оперативной базы мира
- **Атомы:** D-07, D-08, D-19.
- **Зависит от:** T-01-01.
- **Создаётся:** `engine/internal/db/schema/world/0001_init.sql`.
- **Правится:** `engine/internal/db/migrate.go`.
- **Писатель:** ядро (все таблицы), кроме `places`, `paths`, `world_meta` — за Гефестом.
- **Шаги:**
  1. Описать таблицы …
  2. Добавить миграцию …
- **Проверка:** `…команда…` → ожидаемый результат.
- **Исполнитель:** код.
```

Правила заполнения:

1. **Атомы** — только ID из `fine/04-spec`, через запятую. Если задача не
   реализует атом, а готовит инструмент — ссылка на рамку (`F-12.5`) или
   задача помечается «инфраструктура» без атомов.
2. **Зависит от** — ID задач, закрытых до старта. Пусто — старт с начала волны.
3. **Файлы** — точный путь от `TNS65/`. Новый файл — «создаётся», старый —
   «правится». Пути без «примерно» и без глобов.
4. **Писатель** — кто пишет в базу: `ядро`, `Гефест/Forge`, `оседание`, `нет записи`.
   Нужен для сквозного гейта «один писатель» (D-09.7, F-12.2).
5. **Шаги** — пронумерованные, один глагол действия на шаг. Никаких «и также
   не забыть»: каждый шаг проверяем.
6. **Проверка** — одна команда, которую можно скопировать в шелл, и ожидаемый
   результат словами: `exit 0`, «вывод пуст», «ровно 96 строк», «в журнале
   строка `netgate.deny`». Проверка не должна требовать интерактивности.
7. **Исполнитель** — `код` (юнит-тест или команда), `ядро станка` (поведение
   в рантайме), `модель` (LLM-роль, проверяется по журналу), `владелец`
   (только приёмочные сценарии Ф8 и решения вилок).

Запрещено в задачах:

- код в тексте задачи (план не содержит реализации, только действия и контракты);
- «и так далее», «аналогично» — задача описывается до конца;
- проверки вида «убедиться, что работает»;
- ссылки на память агента и на чат: всё нужное — в спеке и в этом плане.

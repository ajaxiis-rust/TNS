# P8. Приёмка

Цель волны: доказать, что станок играет целиком, а не по частям. Девять сквозных
сценариев из `fine/04-spec/09-acceptance.md` прогоняются на собранном бинарнике,
на чистом каталоге данных, с заранее известным исходом. Каждый сценарий —
отдельная задача с одной командой и одним ожидаемым результатом.

Сквозные сценарии живут в `engine/e2e/` на Go с build-тегом `e2e`: каждый —
отдельный тест, который сам готовит каталог `world_db/` в `t.TempDir()`,
поднимает ядро собранного бинарника как процесс, подаёт реплики через HTTP API
и проверяет базы драйвером Go. Хуки `--fake-clock`, `--fake-embed`, `--fake-slot`
включаются в бинарник только с тегом `e2e` и отсутствуют в релизной сборке.
Отчёты складываются в `engine/e2e/reports/<ID>.json` из теста, код возврата 0 —
сценарий пройден. Bash, Python и `sqlite3` CLI в приёмке не участвуют.
Сквозные гейты P0 действуют и здесь: сеть, порты, один писатель, размерность,
честный журнал.

### T-09-01. INT-1. Рождение мира целиком
- **Атомы:** INT-1, B-01, B-05, B-08, B-09, B-10.
- **Выдержки атомов:** INT-1 — форма 14 полей, ровно 96 карточек, один якорь без LLM; пустой синопсис блокирует рождение.
- **Зависит от:** T-02-01…T-02-07, T-02-15, T-02-16, T-08-05, T-08-15.
- **Создаётся:** `engine/e2e/{harness_test.go,int1_birth_test.go}`.
- **Правится:** `engine/cmd/tns65/main.go` (хуки `--fake-clock/--fake-embed/--fake-slot` под build-тегом `e2e`), `engine/e2e/reports/` (каталог отчётов, в `.gitignore`).
- **Писатель:** `core` — проверяет записи, сам не пишет.
- **Шаги:**
  1. Харнесс (общий для всех INT): собрать бинарник с тегом `e2e`, поднять ядро как процесс во временном `world_db/`, ждать `/api/health`, подавать реплики `POST /api/turn`, читать базы драйвером Go, стоп по SIGTERM, отчёт JSON; тест `TestNoE2eHooksInRelease` проверяет отсутствие хуков в обычной сборке.
  2. `tns65 world birth --ancketa <файл>` с анкетой из 14 полей (эмбеддер — `--fake-embed`, детерминированный 1024); остановка ядра после рождения.
  3. Проверить пачку: `characters` = 96, пары «психотип — сословие» уникальны.
  4. Проверить якорь: `anchor_narrative_id` непуст, ровно один; в журнале за время рождения нет ни одного вызова слота прозы (`--fake-slot` со счётчиком).
  5. Прогнать отказ: анкета с пустым синопсисом → код 2, каталог мира не создан.
  6. Прогнать принудительный якорь: синопсис без близких нарративов → якорь всё равно назначен (`forced=true`).
- **Проверка:** `cd engine && go test -tags e2e ./e2e -run TestINT1 -count=1 -v` → PASS, отчёт `reports/int1.json`: `cards=96`, `anchors=1`, `llm_calls=0`, `empty_synopsis_exit=2`, `forced_anchor=true`.
- **Исполнитель:** код.

### T-09-03. INT-3. Смерть внешнего слота
- **Атомы:** INT-3, MD-02, MD-06, MD-07, LT-14, F-09.
- **Выдержки атомов:** INT-3.5 — деградированный ход честно проще: проза запаски короче и проще штатной, без глубокой сцены.

## Выход волны P8: релизный пакет

Девять сценариев зелёные → собирается релизный пакет одной версии (F-12.5):

1. `bash engine/scripts/build.sh` — бинарники ядра трёх платформ, копия текущей ОС, `tns65-bake` и `tns65-lemmaru` одной версии (хуки `--fake-*` в релизной сборке отсутствуют — проверено T-09-01).
2. `bash engine/scripts/gates.sh` — `gofmt` пусто, `go vet` чисто, `go test ./... -race -count=1` зелено на чистом прогоне, `ui-check.sh release` зелено.
3. `cd engine && go test -tags e2e ./e2e -count=1` — девять отчётов, все с кодом 0.
4. `ss -H -lntp | grep tns65 | awk '{print $4}'` — слушающие сокеты процесса только на loopback из белого списка; порт-гейт при старте чист.
5. Пакет языкового пакета `packs/ru` с версией и контрольными суммами; запечённый `base.db` с суммой; файлы `NOTICE` — лицензионные уведомления OpenCorpora (CC BY-SA 4.0) и gomorphy (MIT) в релизном пакете (B-1).
6. Владелец проходит один живой сценарий руками по чек-листу (рождение → три реплики → пауза → глава → экспорт): шаг, ожидаемый вид экрана, где смотреть журнал, критерий «стоп»; результат записывается в `99-LEDGER.md` строкой владельца. Это единственная проверка волны, где исполнитель — владелец, и она не заменяет девять автоматических.

С этого момента станок готов к игре; дальше — новые языковые пакеты (свои лемматизаторы по образцу D-13) и подключение внешнего провайдера Gemini (T-03-18, после готовности движка и UI).

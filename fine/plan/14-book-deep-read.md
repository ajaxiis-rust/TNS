# P13. Глубокий разбор книги: словари по ключам, salience, спорные — слоту

Статус: план на согласование, 2026-11-05.
Норма: этот файл + `fine/04-spec` (атомы W-22…W-28, D-20); при расхождении действует атом спеки.
Основание: решения владельца от 2026-11-05 (раздел 1).

Волна P13 углубляет карту книги (P11, §5.9 и W-14.12) до полного разбора книги
полки: теги чанков по девяти категориям, персонажи с контекстными векторами,
места и сцены, стилевой и драматический профиль, кандидаты пополнения словарей.
Первичный слой работает без модели; модель получает только спорные случаи —
ранжированный топ-K узких вопросов с цитатами, локальным слотом. Всё считается
один раз при варке книги; ключ пересчёта — хеш текста, версия словарей и модель
эмбеддинга.

## 1. Решения владельца (2026-11-05)

| № | Решение | Следствие |
|---|---|---|
| 1 | Обработка первичная: до отдачи текстов в LLM работает слой словарей + морфология + эмбеддинги; слот получает только спорные вопросы | атом W-23 (триада), W-24 (топ-K, локальный слот) |
| 2 | Локальной модели достаточно: выбор из канона с цитатой, без свободных суждений | контракт W-24.2–4 |
| 3 | Триада «уверенно/брак/спорно»; пороги — данные конфига, калибровка один раз на золотом отрывке | атом W-23, задача T-14-06 |
| 4 | Векторы разбора — в literary.db, своими таблицами; таблица `vectors` литературной базы | атом D-20 |
| 5 | Автодополнение словарей — staging в literary.db, промоушен только владельцем правкой пака | атом W-28 |
| 6 | Автор — метаданные парсера + стилевой профиль книги; сравнение отпечатков отложено до заполненной полки | атом W-27 |
| 7 | Лимита чанков на разбор нет: режем всю книгу, варка фоном | задача T-14-13 |
| 8 | Золотой отрывок: черновик разметки готовит станок (субагент), утверждает владелец | `fine/golden/ru/`, W-23.4 |

## 3. Контракты волны

Ключи конфига (`engine/config.yaml`, секция `deepread`; дефолты — данные):

```yaml
deepread:
  thresholds:
    confident: 0.6   # полоса «уверенно»
    reject: 0.15     # полоса «брак»
  slot_budget: 20    # вопросов слоту на книгу
  slot_batch: 5      # вопросов в одном вызове
  alias_cosine: 0.85 # слияние кандидатов персонажей
  staging_cosine: 0.8 # порог кандидата в dict_staging
  golden_min_precision: 0.7 # гейт золотых отрывков
  rating_16: 0.05    # доля confident-чанков erotic/violence для предложения 16+
  rating_18: 0.15    # доля confident-чанков erotic/violence для предложения 18+
```

Версия словарей разбора: `dict_version` = первые 12 символов sha256
`packs/ru/manifest.json`. Модель эмбеддинга: имя модели слота embed. Ключ
пересчёта разбора: `(text_hash книги, dict_version, embed_model)` — D-20.3.

Миграция `engine/internal/db/schema/literary/0006_book_deepread.sql`:

```sql
CREATE TABLE book_chunk_tag (
    chunk_id INTEGER NOT NULL REFERENCES book_chunk(id),
    key TEXT NOT NULL,
    score REAL NOT NULL,
    band TEXT NOT NULL CHECK (band IN ('confident','reject','uncertain')),
    anchors TEXT NOT NULL DEFAULT '[]',
    PRIMARY KEY (chunk_id, key)
);

CREATE TABLE book_place (
    id INTEGER PRIMARY KEY,
    book_id INTEGER NOT NULL REFERENCES book(id),
    name TEXT NOT NULL,
    aliases TEXT NOT NULL DEFAULT '[]',
    kind TEXT NOT NULL DEFAULT '',
    first_chunk INTEGER NOT NULL DEFAULT 0,
    last_chunk INTEGER NOT NULL DEFAULT 0,
    mentions INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE book_scene (
    id INTEGER PRIMARY KEY,
    book_id INTEGER NOT NULL REFERENCES book(id),
    ord INTEGER NOT NULL,
    from_chunk INTEGER NOT NULL,
    to_chunk INTEGER NOT NULL,
    place_id INTEGER REFERENCES book_place(id),
    time_marker TEXT NOT NULL DEFAULT '',
    participants TEXT NOT NULL DEFAULT '[]',
    tags TEXT NOT NULL DEFAULT '[]',
    emotion TEXT NOT NULL DEFAULT '{}',
    UNIQUE (book_id, ord)
);

CREATE TABLE book_style (
    book_id INTEGER PRIMARY KEY REFERENCES book(id),
    author TEXT NOT NULL DEFAULT '',
    features TEXT NOT NULL DEFAULT '{}',
    labels TEXT NOT NULL DEFAULT '[]',
    drama_profile TEXT NOT NULL DEFAULT '[]',
    computed_at TEXT NOT NULL
);

CREATE TABLE dict_staging (
    id INTEGER PRIMARY KEY,
    dict_key TEXT NOT NULL,
    lemma TEXT NOT NULL,
    weight INTEGER NOT NULL DEFAULT 1,
    evidence TEXT NOT NULL DEFAULT '',
    book_id INTEGER REFERENCES book(id),
    status TEXT NOT NULL DEFAULT 'candidate'
        CHECK (status IN ('candidate','promoted','rejected')),
    repeats INTEGER NOT NULL DEFAULT 1,
    created_at TEXT NOT NULL,
    promoted_at TEXT,
    UNIQUE (dict_key, lemma)
);
```

Векторы разбора — таблица `vectors` literary.db (T-14-02), `owner_table` ∈
`book_character`, `book_scene`, `dict_anchor`; якорь категории (`dict_anchor`)
— центроид векторов чанков с полосой «уверенно» по ключу категории, строится
на золотом отрывке и каждой книге, `owner_id` = id ключа из реестра ключей
(`internal/deepread`: ключи категорий фиксированы кодом по W-22.1).

Категории словарей (ключи): `appearance`, `clothing`, `nature`,
`architecture`, `emotion`, `action_dramatic`, `speech`, `time`, `social`,
`erotic` (интим нейтральной лексикой), `violence` (насилие, драки, ранения,
гибель — личный масштаб), `battle` (битвы и война — массовый масштаб);
`character` — седьмая ось `descriptions.json` для карточек, тегом чанка не
является. Файлы пака: существующие `descriptions.json`, `detectors_mood.json`,
`detectors_time.json`; новые `nature.json`, `architecture.json`, `social.json`,
`action_dramatic.json`, `erotic.json`, `violence.json`, `battle.json`,
`styles.json` (канон ярлыков стиля, W-27.2).

Формат файла словаря категории:

```json
{"lemmas": {"лес": 1, "виднеться": 1, "пустыня": 2}, "phrases": []}
```

`phrases` — композиции ключей («виднеться» + существительное `nature`) вторым
шагом волны не заполняются; поле зафиксировано, чтобы не менять формат.

### T-14-05. Salience и теги чанков: триада
- **Атомы:** W-22, W-23.
- **Выдержки атомов:** W-23.1 — «Скор категории чанка — salience: взвешенная сумма IDF-весов лемм словаря против фона книги; сырые счётчики совпадений порогом не являются»; W-23.3 — «На чанк пишется тег каждой категории с полосой и до трёх якорных цитат — подстрок чанка с опорными леммами».
- **Зависит от:** T-14-01, T-14-03, T-14-04.
- **Читать:** §3 этого файла (ключи конфига), `engine/internal/workshop/forge_book.go` (контур прогона).
- **Создаётся:** `engine/internal/deepread/salience.go`, `engine/internal/deepread/salience_test.go`, `engine/internal/deepread/store.go`.
- **Правится:** `engine/config.yaml` (секция `deepread` с дефолтами §3).
- **Писатель:** `forge` — строки `book_chunk_tag` в literary.db.
- **Шаги:**
  1. Посчитать IDF лемм по книге: `idf = log(1 + N / (1 + df))`, N — чанков, df — чанков с леммой.
  2. Скор ключа чанка: сумма `вес словаря × idf` по леммам словаря в чанке, нормированная в 0..1 по максимуму ключа на книге.
  3. Полоса: `score ≥ thresholds.confident` → `confident`; `score ≤ thresholds.reject` → `reject`; иначе `uncertain`; пороги читаются из конфига.
  4. Якоря: до трёх подстрок чанка вокруг опорных лемм (окно ±2 предложения), сохраняются в `anchors` как JSON-массив строк.
  5. Запись тегов в `book_chunk_tag` (ключ × чанк, `PRIMARY KEY (chunk_id, key)`), идемпотентно — повторная запись заменяет строки чанка.
  6. Тест: фикстура из пяти чанков (пейзажный, интерьерный, боевой, диалоговый, пустой связный) — полосы и якоря соответствуют разметке фикстуры; смена порогов в конфиге меняет полосы.
- **Проверка:** `cd engine && bash scripts/runtests.sh ./internal/deepread TestSalienceBands` → PASS: пейзажный чанк — `nature=confident` с якорем-подстрокой; пустой чанк — все ключи `reject`; порог 0.99 переводит пейзажный в `uncertain`.
- **Документы:** `engine/config.yaml` (дефолты — данные), `engine/ARCHITECTURE.md` (пакет deepread).
- **Исполнитель:** код.

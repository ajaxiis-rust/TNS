# Бэклог рисков для плана разработки (из внешней критики 18.10)

Спецификацию эти пункты не меняют (проверено сверкой с атомами); это вход для этапа планирования.

1. Вертикальные срезы в порядке: рождение (анкета → 96 карточек → якорь, три базы) → скелет конвейера хода (happy-path + путь банка + путь Ткача + стоп-кран) → оседание → мастерская (очереди, приоритеты) → Паганель (кольца) → книга (дайджест, цензор правок, экспорт).
2. DDL трёх баз и карта писателей таблиц (D-09, D-10, D-19) — до любой бизнес-логики.
3. Golden-тесты оседания: файлы «до/после очистки», контроль дедупа по смыслу и уровня доверия; без стабильного пайплайна оседания банк деградирует.
4. Наблюдаемость хода: журнал пишет рекомендацию Пилы, решение Селектора, путь (банк/Ткач/оседание), уровень доверия записи, деградации слотов.
5. Бюджет производительности: 4 ядра против резидентов ~0,1 + 2,4 ГБ; приоритет живого хода над мастерской обеспечить механизмом (пулы/лимиты), а не только нормой W-01.
6. Плотность MCP и «Настроек» на телефоне — отдельная проверка UI-среза.
7. Контракт сменного языкового пакета (D-11, D-12) вынести жёстче при планировании мультиязычности.
8. Стоимость внешних слотов: мониторинг квот и счетов — задача плана.
9. F-04 (только исходящие соединения, нет слушающих сокетов) — сквозное требование готовности для всех инфраструктурных задач.

Справочно: миграция base.db при смене эмбеддинг-модели уже нормирована в 01-data (пересчёт обязателен, векторы разных моделей не смешиваются, приёмка ловит смешение); пошаговый рецепт пересчёта — задача плана.

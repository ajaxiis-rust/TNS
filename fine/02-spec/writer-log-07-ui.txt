+# 07-ui — Карта интерфейса
+
+Интерфейс станка разделён на две части: игроковую и админскую. Админская часть игрокам недоступна; первым это зафиксировал раздел управления моделями (канон п.14, R-017). Источник состава окон и полей — банк решений `interface/`: формы и вкладки там уже разобраны, и переделка разрешающего вопроса не требует нигде, где пример молчит или канон не спорит с ним (R-164). Права на этом разделении такие: администратор станка настраивает слоты, ключи и параметры, игрок работает только со своей книгой и своим миром, а владелец вне операционного цикла — он видит журналы и интерфейс пост-фактум и вмешивается распоряжением (R-006, R-163).
+
+## Разделение игрок/админ
+
+Админская зона скрыта от игроков (R-017). Игроку доступен чат живого хода, окно «Моя книга», «Прорисовка карты» и «Граф отношений» — других игроковых окон нет (R-020, канон п.16). Всё остальное — миры, конфигурация мира, роли, провайдеры, модели, дашборд, граф-крафт, консоль наполнения, настройки — принадлежит админ-зоне (R-017, канон п.14).
+
+## Игроковые окна
+
+**Чат.** Основное окно живого хода: поле реплики, вкладки мир/герой/система, служебные команды, кнопка BOOK, открывающая окно «Моя книга» (R-155, R-017). Верхняя строка чата несёт индикатор здоровья памяти, метку ветки, точки статуса API и WebSocket, часы и кнопки перехода по разделам (R-155). Ряд быстрых команд — /статус, /осмотр, /квесты, /помощь — отвечает на служебные команды игрока; они дополняют прозу, а не заменяют её, и мир отвечает на обе формы (R-155, R-018). Действия управляют сессией: CLR очищает поле, SAVE сохраняет сессию в markdown, LOAD открывает модал сохранённых сессий, BOOK открывает книгу (R-155). Боковая панель имеет три вкладки — мир (обзор графа: узлы и рёбра), герой (текущий персонаж), система (статус API и WebSocket); это канонические вкладки мир/герой/система (R-155).
+
+**«Моя книга».** Модальное окно, текстовый редактор; игрок открывает его кнопкой BOOK из меню (R-156, R-163, канон п.13). Сверху стоит полоса дайджеста: краткое содержание текущей главы из 5–6 предложений, которое пишет Редактор после обработки текста главы (R-156, канон п.13). Дайджест — сводка только для игрока; сводка мастерской — отдельный термин и в игроковое окно не попадает (R-145). Ниже четыре вкладки: «Содержание» (список глав и навигация по нему, заполняется по мере закрытия глав), «Глава» (полный отредактированный текст главы в режиме редактора), «Правки Цензора» (что Редактор менял, что отклонено, в виде «было → стало») и «Сырой лог» (неотредактированный лог сессии, опционально) (R-156, канон п.13). Вкладка «Глава» работает как режим редактора: игрок правит свои ошибки прямо в тексте (R-156, R-163, канон п.13). Правка, не прошедшая проверку Цензора правок, в книгу не попадает и остаётся видимой игроку во вкладке правок (R-062, R-145).
+
+**«Прорисовка карты».** Карта мира дорисовывается по мере путешествий героя; это игроковое имя картографа, внутренняя роль Паганель игроку не показывается (R-020, R-019, канон п.16). Данные карты живут в world(name).db, карта — вьюпорт над ними, рендеринг локальный: без наружных библиотек и тайлов (R-020, канон п.16). Рендеринг идёт на локальных данных GeoJSON; шаблон с CDN и внешними тайлами для копирования не годится, годится шаблон «land.json + canvas» (R-165).
+
+**«Граф отношений».** Связи между персонажами: граф строит движок из социального графа и подаёт игроку (R-020, канон п.15). Игроку-писателю он служит рабочим инструментом контроля нитей, игроку-подростку — небольшой подсказкой о том, кто с кем связан (R-020, канон п.15).

+## Правило имён
+
+Имена ролей — Ткач, Челнок, Пила, Паганель и остальные — являются код-именами: они живут в каноне и коде и игроку не показываются (R-019, канон п.16). Прецедент разделения словарей — «дайджест» для игрока против «сводки» мастерской (R-019). Правило действует одинаково для всех игроковых окон и не распространяется на админ-зону, где слоты ролей называются своими именами (R-017, R-019).

+## Дельты UI против канона
+
+Три места интерфейса расходятся с каноном и значатся backlog'ом правки при реализации (R-160).
+
+Первая дельта — жанр: в конфигурации мира он свободный текст с подсказкой-примером, тогда как канон требует фиксированного списка из десяти жанров с множественным выбором; потребитель жанров — вставка Паганеля (R-160, R-024). В форме создания мира эта дельта уже закрыта: там стоят десять флажков, совпадающих с каноническим списком (R-157).
+
+Вторая дельта — embeddingDimension: в настройках по умолчанию 384, а размерность эмбеддинга BGE-M3 равна 1024, и владелец подтвердил точное значение 1024; дефолт 384 помечен как устаревший, в интерфейсе его надо заменить на 1024 (R-160, R-154, решение владельца 17.10).
+
+Третья дельта — режим походов: поля нет ни в форме создания мира, ни в конфигурации мира, тогда как канон требует явного поля анкеты со значениями реальная, вымышленная, смешанная, не выводимыми из жанров (R-160, R-024). В форме создания мира это поле тоже отсутствует (R-157).
+
+Дополнительно спека фиксирует расхождение по Цензуре: отдельной формулировки «Цензура 16+/18+» в UI нет, есть только выбор рейтинга 16+/18+; рейтинг наложен на цензуру при ковке по канону, поэтому при правке достаточно назвать поле его каноническим именем (R-160, R-024, канон п.13). Статус всех дельт — backlog, решение по смыслу полей уже принято и пересмотру здесь не подлежит (R-160).

+## Правило исполнителя в интерфейсе
+
+Каждый гейт интерфейса называет исполнителя — код или модель; человек из операционного цикла исключён (R-006). Практически это значит: настройки слотов и ключей выполняет администратор станка руками интерфейса, но сами проверки и переходы — назначение слота, проверка целостности модели, проверка правок Цензором, рендеринг карты, наполнение панели графа — выполняет код или модель (R-006, R-017). Владелец видит журналы и интерфейс пост-фактум и вмешивается распоряжением, а не кнопкой в живом контуре (R-006, R-163).
+
+Критерий успеха интерфейсной фичи тот же, что у любой другой: текст книги становится интереснее постороннему читателю; решения и чувства игрока неприкосновенны, допускается один мягкий намёк, второй отказ означает остановку; мир учится литературным предпочтениям, а не личности; терапевтические и навязчивые функции вне рамок (R-005).

# Золотой отрывок ru-homonyms — омонимы волны 15

Отрывок для гейта точности разбора книг (TNS65) на омонимах смыслового слоя (T-15-02).
Остальные отрывки (`ru`, `ru-battle`, `ru-erotic`) показывают категории на связной прозе,
этот — на словах, у которых смыслов расходятся по категориям: замок-строение и
замок-запирающее, ключ-родник и ключ-отворотка, свет-освещение и свет-общество и т. д.

## Схема `golden.json`

Гейт `TestGoldenPrecision` читает из `golden.json` только `approved` и `chunks[]`
(`id`, `para_from`, `para_to`, `words`, `categories{ключ: {present}}`); остальные поля —
пометки для человека, код их игнорирует.

- `approved: true` — разметка принята владельцем; без флага отрывок пропускается.
- `present: true` — категория действительно есть в чанке; `present: false` — её нет.
  Гейт считает precision только по confident-тегам, поэтому `present: true` ставится там,
  где категория читается по тексту, а не там, где её нашёл salience.
- `homonym`, `sense` — лемма волны и её смысл в этом чанке (ожидание смыслового слоя).
- `words` — число слов абзаца; расхождение с нарезкой `excerpt.txt` — ошибка гейта.

## Как гонять

```
cd engine && bash scripts/runtests.sh ./internal/deepread TestGoldenPrecision TestSenseSalience
cd engine && go test ./internal/deepread -run TestGoldenPrecision -count=1 -v
```

Смысловой слой проверяется отдельно (`TestSenseSalience`): ловушка-омоним не даёт ложного тега
категории, нерешённый смысл считается консервативно, порог `deepread.senses_margin` снимает
решение. Сам гейт `TestGoldenPrecision` считает теги без смыслового слоя — он держит точность
отрывка на омонимах, чтобы смысловая правка не прятала регрессию обычного счёта.

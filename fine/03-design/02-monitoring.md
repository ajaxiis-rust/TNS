# 02-monitoring — Мониторинг: дизайн первого экрана

Решение владельца 17.10 (вечер): первый экран утверждён по проекту. Место — Настройки, раздел «Мониторинг». Характер — пост-фактум и только чтение: журналы видны, вмешательства кнопками нет — вмешательство идёт распоряжением, не в контуре (R-006, канон п.14). Обновление живое (WebSocket), как статусы чата; имена ролей — код-имена, в Настройках допустимы (R-019, решение владельца 17.10).

## Первый экран, по убыванию важности

1. **Слоты и провайдеры** — онлайн да/нет, валидность ключа, остаток лимита вызовов (если API отдаёт).
2. **Роли** — по каждой роли: вызовов, ошибок, процент ошибок, среднее время ответа, время последнего вызова.
3. **Локальные машины** — генерация (:5001) и эмбеддинг (:5002): жива/мертва, длина очереди.
4. **Деградации хода** — сколько раз ход ушёл на запасной путь вместо внешнего слота.
5. **Хвост журнала станка** — последние строки журнала, только чтение.

## Границы

- Ковка наполнения и кольца Паганеля показываются дашбордом вкладки MCP и здесь не дублируются.
- Управление из Мониторинга отсутствует: раздел не содержит кнопок, меняющих состояние станка.
- Первый срез показателей берётся из журнала вызовов; глубина истории и графики — при реализации, отдельным решением.

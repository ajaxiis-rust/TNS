# 01-mcp — Вкладка «MCP»: дизайн консоли наполнения

Дизайн вкладки «MCP» главного интерфейса. Состав подтверждён владельцем 17.10 и доработан решениями вечера 17.10. Вкладка — консоль наполнения и станочных инструментов: наполнение есть работа с базами, а не живой ход; вкладка доступна игроку наравне со всем интерфейсом (решение владельца 17.10). Один экран, без подвкладок; боковых меню в интерфейсе нет, дизайн адаптивный, включая телефон (решение владельца 17.10).

Состав экрана, сверху вниз: дашборд ковки, книги-источники, кольца Паганеля, инструменты станка. Экран реализован в банке решений: `interface/mcp.html` — восемь вкладок старого дома переделаны в этот состав (решение владельца 17.10; нарративы, справочник эпох, шаблоны, экономика-фаза и системные экраны вырезаны, делексификация осталась инструментом раздела книг).

## 1. Дашборд ковки

Живое состояние конвейера наполнения (обновление через WebSocket, как статусы чата):

- очередь наполнения — работы по книгам и кольцам, в штуках;
- процент выполнения текущей работы;
- статистика: книг обработано, глав разобрано, шаблонов снято, отклонено Цензором при варке, замен при делексификации, ошибок.

Делексификация и проверка фактов — автоматические шаги конвейера; в интерфейсе они видны только как счётчики дашборда и записи журнала, отдельных кнопок нет (решение владельца 17.10).

## 2. Книги-источники

Файлы книг игрок скачивает самостоятельно, вне движка; скачивальщика корпусов и каталога Project Gutenberg во вкладке нет (решение владельца 18.10). Вкладка получает уже скачанные файлы импортом.

Карточки книг: имя, формат (txt/fb2), статус конвейера (в очереди / куется N% / готова / ошибка), счётчики — глав всего, разобрано, шаблонов в базу. Кнопки: импорт новой книги, запуск ковки, удаление сырья.

- Импорт: выбор файла; fb2 конвертируется вставкой перед чанкером (п.18), txt/md читает парсер напрямую.
- Ковка книги: конвейер разбора глав — наследие TNS35 (DramaturgicPass), классификатор архетипа исполняет внешняя модель; результат через Цензора при варке попадает в literary.db.
- Сырьё живёт файлами в папке мира, в базы входит только выкованное (R-140, R-026): удаление сырья готовое в базе не трогает.

## 3. Кольца Паганеля

Паганель — часть консоли наполнения, его работа отражена отдельной карточкой: прогресс по кольцам (решение владельца 17.10, вечер).

- Очередь колец и текущее кольцо, процент готовности; обработки идут в паузах и простое игрока (п.7, п.16) — в простое карточка показывает идущую ковку колец.
- Счётчики: места и пути, включая неявные («к вечеру добрались до…»), упомянутые люди; статусы записей draft → baked — в baked продвигает код после проверок (п.16).
- Журнал колец живёт здесь (канон п.16: «журнал колец — в UI»).

Переключатели «включён» и «походы наружу» и ключ внешней модели остаются в Настройках → World (R-153) и здесь не дублируются: карточка показывает прогресс, не управление.

## 4. Инструменты станка

### Коэффициенты

Кнопка открывает модальное окно математического анализа и обработки ходов: все коэффициенты, которые станок задаёт и вычисляет для ходов и ответов без LLM, — веса пересчёта, пороги, тайминги, экономические циклы (решение владельца 17.10, вечер).

- Разрез: только станочное, общее для всех миров. Мировые параметры — анкета, globalLuck, норма дня — заморожены при рождении мира (решение 17.10) и в модал не входят.
- Правка применяется к будущим просчётам; история мира не пересчитывается.
- Сохранение идёт с предупреждением «меняет пересчёт и логику ходов»; каждое изменение пишется в журнал: было → стало, когда.

### Лемматизатор

Карточка языкового пакета: какой лемматизатор стоит (русский пакет — pymorphy3, п.4, R-008) и его параметры. Для пакета другого языка — своя библиотека; английский может работать без лемматизатора — переключатель (решение владельца 17.10, вечер).

## Отладка — журналом, без экранов

Справочник эпох и литературные шаблоны собственных экранов не имеют (решение владельца 17.10): игроку не нужны, отладка разработчика идёт по журналу ковки. Журнал пишет машина, каждая запись несёт статус (draft → baked), происхождение (книга / справочник эпох / оседание), вердикт Цензора при варке, уровень доверия, счётчики делексификации и проверки фактов. Чтение — файлом; отдельного раздела интерфейса нет.

Нарративы base.db игроку не показываются вообще (решение владельца 17.10): каталог лишний, база заморожена после сборки (01-data §1.1).

## Правила

- Имена ролей: во вкладке MCP допускаются код-имена — Паганель, Гефест, Цензор (R-019, решение владельца 17.10).
- Исполнитель — код или модель, человек вне операционного цикла (R-006): игрок запускает работу и читает результат.
- Права баз не меняются: живой ход пишет только оперативную базу; наполнение пополняет literary.db через Цензора при варке и world(name).db по местам и путям (01-data §2, R-139).
- Запекание сида — внеигровой инструмент предстартовой подготовки — во вкладку не входит (решение владельца 17.10).

# TNS65 — Карточка ремонта документации

Заведена 12.10 по решению владельца после критического разбора парадигмы.
**Цель:** парадигма и спецификации понятны постороннему разработчику полностью, подробно, с примерами.
**Причина:** документ писался как журнал решений для участников; язык агента и его ограниченная память подводят — поэтому носитель формулировок там, где возможно, сам владелец (корпус в RAW), а не пересказ.
**Метод:** маленькие задачи; одна задача = один коммит; после каждой — короткий статус владельцу. Карточки пунктов пишутся по одной.
